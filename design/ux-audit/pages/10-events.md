## 10. 每周活动 `#events` / `#events/<typeId>`
> 计数：P0 5 / P1 6 / P2 2

走查方式：Playwright 无头 chromium，视口 1600×900。两条动线各跑一遍——
**日常循环线**（地图 rail「世界事件」→ `#events` 回退轮值页 → 规则卡 → 出战 → 商店 → 材料）与
**六页横切线**（`#events/<typeId>` 六页逐个进，常态 + 规则卡展开）。
为了把六个专属状态区全逼出来，另跑一遍**轮值模拟**：浏览器内 `Date.now` 偏移 k 周（k = `EVENT_ROTATION` 下标）令目标活动成为轮值周，
同时注入 `eventWeek` 富进度（积分 1180 / 代币 210 / 已领里程碑 [0,1,2] / 六套玩法状态键 / 部分货品买断）。零 `src` 改动，只动浏览器侧时钟与 localStorage。
脚本：`artifacts/ux-audit-scripts/u4-events.mjs`、`u4-events-states.mjs`。
探针日志：`artifacts/ux-audit-scripts/u4-events.log`、`u4-states.log`。
console 错误 **0 条**（两个脚本全程）。本页问题全部是设计层面，不是报错——
用户说「页面设计的一坨，根本没有视觉语言，就是把一大堆字全凑到一起」（UX-4），探针给出的量化就是
**六页 `img/canvas/svg/[data-icon]` 计数全为 0，而纯文字字符数 421~566**。

### 重设计提案

#### P0 · 专项一 · UX-4 视觉语言提案：六个玩法状态区「把字变成图形」

先定三条通则，再逐个活动给控件。

**通则 1 · 什么该升为主视觉**：每个活动有且只有**一个**"我现在在哪儿"的量（防线序号 / 首领血量 / 楼层 / 克制命中数 / 物资数 / 连胜数）。
它必须是整块状态区里唯一的大图形，占状态区 ≥60% 面积，不用文字也能读出来。
**通则 2 · 什么该退成注脚**：规则解释（"战败会退回第 1 条防线"、"每 5 层有首领把守"、"战败清零"）全部退出状态区，
合并进规则卡（E-13 改默认展开）；状态区只留**当前数值**与**下一步动作**。
**通则 3 · 奖励一律带图标**：`rewardSummary()`（`eventsScreen.ts:27-43`）目前输出纯文本串，是 E-3 与 S-2 的共同根因。
应改为返回「图标 + 数量」的结构化数组，最多显示 3 个图标 + 「+N」折叠，全文进 tooltip。
素材侧已有可用图标源：顶栏五货币 `[data-icon]`（`chrome.ts:148-153` 的 key/crystal/swords/…）、
特质石有六色圆点（`gameMain.ts:132-135 STONE_COLOR_HEX`）、钢锭七档可复用稀有度色（`troop.css:.r-0..r-5`）。

### 五问自查

1. **3 秒问题**：**不过关**。三秒内能读出页面标题「每周活动」和一排六个页签，读不出三件事：哪个活动在进行（六分之五是死页 E-1，而活着的那个只靠一个 7px 圆点标记 E-11）、我现在进度到哪（要读文字 E-2/E-4）、下一步点哪。全屏视觉最强的确实是右上角的「迎击」主按钮（紫底金框，`live.css:17`），这一点是做对的；但它旁边没有任何"打这一场我能得到什么"的信息，玩家点它是因为它是唯一亮的东西，不是因为他被说服了。预告页更糟：三秒内看到一个灰按钮写「CLOSED」和 400px 黑屏。

2. **信息主次**：**颠倒**。玩家此刻关心：「我离下一档奖励差多少」「这活动现在什么状态」「代币能买什么」。三件事分别是：藏在 3×2 网格里的 10.5px 灰字（E-3）、写成句子的状态区（E-4）、滚动条以下的商店（E-5）。被排得最响的反而是注脚——`本周积分` 的 22px 金色数字（`live.css:25`）是页面最大的数字，但"积分"本身对玩家没有意义（积分不能花，只是里程碑的刻度）；`LIVE EVENT · INVASION` 这行英文装饰用了 `.3em` 字距占满一行；页脚「6 周轮换 · 每周一 0 点切换」在全开放裁定之后是一条**反信息**。

3. **视觉语言**：**不成立**。这是全仓最严重的一页——`graphics:0`（E-2）意味着这一页没有参与全局的暗金/卡面/纹章/立绘体系，它只用了体系的**底色和描边**。具体表现：所有信息载体都是 `border-radius:10~12px` + `rgba(255,255,255,.07)` 描边的圆角盒子（里程碑、状态区、规则卡、货架、防线节点、预告框——六种语义共用一种外形）；唯一的色彩语义是 `#ffd77a` 金色高亮，它同时表示"当前页签""已达标里程碑""代币数""目标王国名""连胜倍率"五件不同的事；横幅是一道紫→暗红的线性渐变（`live.css:7-9`），与地图/宝箱/图鉴的暗棕金不同源。UX-13（全局视觉语言）在这一页的表现最极端。

4. **操作路径**：**主路径 3 步通，周边全断**。通的：地图 rail → `#events` → 「迎击」，3 步进战斗。断的：想玩指定活动（六分之五点进去是死页 E-1）；想去商店（要在面板内滚动才看见 E-5）；想按提示去编队堆阵营加成（状态区写了"去编队页"但没有链接 E-4/④）；打完想继续（回到 `#events` 根页而不是原活动页 E-10）；想知道什么时候重置（全页无 E-8）；想在活动页看自己有多少特质石以判断石包值不值得买（要去顶栏材料库弹层，见 `13-materials.md`）。

5. **极端态**：逐条实跑过——
   - **预告态（非轮值 ×5）**：不崩，文案清楚（「1 周后开启（9 月 21 日当周）」「届时代币、商店库存与里程碑进度都会重置重来」），按钮正确置灰成 `CLOSED`。但这一态**整体是被裁定废除的**（UX-6），且下半屏 400px 纯黑无任何内容（E-1）。
   - **积分 0 / 代币 0（新周第一次进）**：进度条宽度 0，六档里程碑全灰，四件货品全部带 `.poor` 类（`opacity:.75`，`live.css:120`）**但不 disabled**——点下去才出 toast。探针实测 `goods` 四项全 `poor`、`disabled:false`（`u4-events.log` invasion 段）。这一态是"恰好没崩"，不是设计过的。
   - **代币富余 + 部分售罄**：设计过——`sold-out` 项 `disabled` 且 `opacity:.38`（`live.css:119`），点不动。但界面上不写「售罄」二字，只写「剩余 0」（见 `11-event-shop.md` S-3）。
   - **里程碑已领 / 已达标未领**：两态都有专门样式（`.done` 绿勾 / `.ready` 金边呼吸，`live.css:34-39`），这一块是设计过的。缺的是"下一档差多少"。
   - **末日之塔 · 登塔中 / 未开爬**：两态都有分支（`eventsScreen.ts:193-195`），未开爬时写「尚未开爬 · 出战即开爬」，文案清楚。缺的是队伍残血可视化（E-4/③）与放弃的防误触（E-7）。
   - **突袭首领 · 血池未生成**：设计过——`e.max > 0` 为假时血条满宽并写「首战生成血池」（`eventsScreen.ts:181`）。
   - **阵营突袭 · 命中 0 名**：**没有设计过**。界面输出 `攻击 +0 / 生命 +0`（探针实测就是这个值），读起来像"这活动没有加成"，而不是"你需要去编队"。这是最常见的初见态（新玩家不可能恰好编了目标王国的部队）。
   - **职业试炼 · 主角未编入**：页面**不拦、不提示**，只在折叠的规则卡里写了一句「主角必须编入出战队伍」；硬校验在 `systems/events.ts:eventBattleReady`，即点了出战才被拦。
   - **世界事件 · 加成种族未翻译**：`Daemon` 原样输出（探针 `本周加成种族：Daemon`），与 `04-troop.md` 里 `TYPE_CN` 缺 `Daemon` 条目是同一处缺口。
   - **周末最后一小时**：显示「剩 1 天」（`daysLeft` 向上取整，`eventsScreen.ts:56`），没有任何紧迫表达（E-8）。
