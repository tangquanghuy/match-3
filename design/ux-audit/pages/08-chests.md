### 重设计提案 · UX-9 宝箱拆双页（按 §3A 已裁定口径出线框）

裁定口径复述（`TASK-UX §3A`）：池 A = 金钥匙宝箱 + 荣耀宝箱（同页并列，主视觉=两箱对望图）；
池 B = 宝石宝箱（独立页，主视觉=满箱宝石水晶图）；切换器 = 页顶两个大 banner-tab（各带池名 + 货币角标）；
主视觉占上半屏、文字退到图内压暗区；按钮区收进图下沿；「最近获得」条保留；两池各自独立的开箱统计。

**线框规则八条**
1. **主视觉整张切换**，不做淡入淡出以外的花活；切换时 banner-tab 的"当前"边框与主视觉同步，池身份靠图本身识别（这是二游卡池的核心：认图不认字）。
2. **文字全部退进图内压暗区**（`linear-gradient` 遮罩 + 图内文字），不再占独立的页面行——这是 CH-2（90px 底栏塞三池 174 字）的根治方式。
3. **按钮收进图下沿**：按钮带贴在主视觉底部、压在图上，与图共用一个视觉块。解决 CH-9（图与操作脱钩）。
4. **池 A 左右分区**：金钥匙在左、荣耀在右，与"两箱对望"的构图对应（左箱=钥匙、右箱=荣耀），文字块落在各自箱子下方的压暗区里。
5. **余额角标进 banner-tab**，同时在图内压暗区重复一次——玩家在切换器上就能判断"哪个池我开得起"。
6. **失败态形态化**：钥匙 < 10 时「开启十次」置灰且改文案「还差 N 把」，并把「开启一次」提为主行动（CH-1 的呈现层配套；逻辑层必须同时修，见 CH-1 修法指针）。
7. **最近获得条两池独立**，条目带名字 + 稀有度色边 + 重复角标，并挂「▸ 全部记录」进一个可翻的开箱历史（配合 CH-5 把 `recent` 落存档）。
8. **两池独立统计 + 常驻概率入口**：统计条固定在页脚，「奖池与概率 ▸」从 toast 改为侧抽屉（含荣耀箱，CH-6）。

### 五问自查

1. **3 秒问题**：**部分过关**。三秒内能看出"这是宝箱页"——1200×560 的宝箱大图把这件事说清楚了，这是全仓少数第一眼就成立的页面。不过关的是"下一步点哪"：图上那两个箱子不可点（CH-9），真正的操作是屏幕最底 90px 里六枚小按钮（CH-2），而它们中视觉最强的一枚在余额不足时反而是买不起的荣耀箱（CH-4）。三个池的差异（出什么、有没有保底）在 9px 的错行文字里，三秒内读不到。
2. **信息主次**：**颠倒**。玩家关心：开哪个池、我开得起吗、概率多少、上次开出了什么。四件事分别是：池差异压成 9px 乱码（CH-2）、余额不足只有滤镜提示（CH-4）、概率塞一条会消失的 toast（CH-6）、最近获得是 29px 无标签缩略图且切页即空（CH-5）。被排得最响的是一张**纯装饰的 JPEG**（占 62% 面积、不可交互、还和池数量对不上，CH-3/CH-9）。
3. **视觉语言**：**这一页是全仓最好的，但也最经不起放大**。暗金框 + 木箱质感 + 金色实底按钮 + 紫色宝石按钮的分池配色（`screens.css:869-871`）是成立的，开箱演出（序列帧 FX + 传说 slam + 音效，`chestsScreen.ts:14-21,327-393`）是全仓最完整的一处"仪式感"。破功处三个：① 主视觉是放大 1.17× 的 JPEG（CH-3）；② 底栏 9px 文字互相穿插（CH-2）；③ 宝石池的卡背是木箱（CH-8），演出与池身份脱节。
4. **操作路径**：**主路径 2 步通，边界全是坑**。通的：`#chests` → 点池按钮 → 演出 → 收下，2 步。坑的：钥匙 7 把点十连 = 扣光 + 零反馈 + 错误 toast（CH-1，**这条不是别扭，是资源损失**）；余额不足只能逐个点试（CH-4）；想复看概率只能反复点 toast（CH-6）；荣耀箱开完页面无变化（CH-7）；想确认素材进账要去顶栏材料库弹层（`13-materials.md`）；最近获得切页即空（CH-5）。
5. **极端态**：逐条实跑过——
   - **余额全部不足**（gold 0 / soul 0 / gem 4 / key 0 / glory 3）：五个按钮全标 `is-unaffordable` 但全部可点，点了出 toast；探针 `买不起是否开了演出: false`（不会误开演出，这一点是对的）。整体属"恰好没崩"（CH-4）。
   - **钥匙 7/10（部分够）**：**缺陷态**，见 CH-1。这是"恰好没崩"的最坏形态：系统层每笔单抽都是正确的，组合起来却吞了资源。
   - **最近获得 · 空**：有专门空态（条内留空 + 标签仍在，截图 `chests-recent-empty.png`），但它同时是"切页后"的常态（CH-5），所以这个空态玩家看到的次数远超预期。
   - **荣耀箱只出素材（无卡）**：有专门分支（`chestsScreen.ts:290-293`），不崩，但反馈只有 toast（CH-7）。
   - **十连保底**：设计过且实现在数值层（`GEM_CHEST` 十连必得 Epic+，`gacha` 最后一抽结算），演出层也有 epic/legend 分档 FX（`fxClassOf()` `chestsScreen.ts:48-53`）。探针十连实测 `counter "10 / 10"`、`revealed 10`、`status "开启完成"`，流程完整。
   - **翻牌中途关弹层**（Esc / 点遮罩）：有处理（`:180-182` Esc + `data-summon-close`），`closeSummon()` 清定时器与 FX 并刷新余额——卡已入账（`drawRewards` 早于演出），不会丢奖励。这一态是设计过的。
   - **传说 slam**：单独一套演出 + `slamLocked` 防连点（`:359-366,404-433`），设计过。
   - **重复获得**：`duplicate` 字段在卡面 label 上有「· 重复」（`:314`），但**最近获得条里没有**（CH-5）。
   - **图片加载失败**：卡面与最近获得都有 `onerror` 兜底切本地立绘（`:192,313`），设计过。
