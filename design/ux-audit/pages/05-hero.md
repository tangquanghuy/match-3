### 重设计提案

#### P0 · H-1 + H-2 + H-4：武器库从「一屏装完」改成「可检索的收藏页」（线框）

当前结构的根问题是：一个 646px 固定高的弹层里塞了「20 把武器 + 详情 + 熔炉入口」，于是列表被裁、按钮被顶出去、分母还写着 730。
弹层撑不下这件事，**升级为独立屏 `#weapons`**（与 `07-weapons-codex.md` 的图鉴并入方案共用骨架，见那份的 C-1 提案），弹层只保留"快速换装"这一件事：

必须同时满足的四条硬约束（每条对应一个已实测的坏点）：
1. **网格区自己有 `overflow-y:auto`**，且不可达 tile 数必须为 0（H-1 的验收口径就是复跑 `artifacts/ux-audit-scripts/u3-probe.mjs` 看 `fullyUnreachable`）。
2. **操作条 sticky 在详情列底部**，不再用 `margin-top:auto` 把按钮推到内容流末尾（H-2 根因 `screens.css:1988`）。
3. **分母诚实**：`我的武器 N`（=`unlockedWeapons.length`）/ `全部 730`（可浏览但标「未拥有 · 暂无获取途径」）/ `熔炉 9`（当前真能造的）。不要把三个数混成一个「5 / 730」。
4. **未拥有态要说清怎么拿**：目录武器目前只有 9 把有途径，其余 701 把应显式写「暂未开放获取」——这比让玩家自己找一圈更诚实。

#### P0 · H-3 / UX-2：贴图统一方案

**先把事实摆清（`u3-catalog-audit.txt` 实测）**：

| 事实 | 数值 |
|---|---|
| `public/gowhead-icons/` 卡面文件数 | **718 张**，与 `weapons.json` 的 718 行**一一对应**（`imageFile 缺失 0 把`、`imageFile 指向的文件不存在 0 把`） |
| 卡面覆盖的 id 空间 | 只覆盖 `gw_<referenceName>`（目录武器），通过 `weaponCatalog.catalogIconUrl()` → `/gowhead-icons/{imageFile}` |
| 首批 20 把 `w_*` 有没有官方卡面 | **一张都没有**。20 把的中文名在 718 目录里精确同名命中 **0 / 20**（学徒法杖、训练长剑、猎手短弓…全是本项目自造名） |
| 20 把里剪影也错的 | **7 / 20** 兜底成长剑（`WEAPON_ICONS` 缺 mace/tome/shield/ring 四键） |
| 若要"找一张官方卡面顶上" | 同类型同稀有度候选池大小已盘完：例如 训练长剑→Sword/Common **2 把**、学徒法杖→Staff/Common **1 把**、猎手短弓→Bow 池里**没有 Common，最低 Rare 3 把**；Epic/UltraRare 档候选普遍 4~54 把 |

**方向 A · 给 20 把 w_* 指认官方卡面**
做法：按「同类型 + 同稀有度」从候选池里各挑一张，写进一张 `w_* → imageFile` 映射表。
代价：20 条人工指认；Common/Bow 这类薄池会**撞脸**（同一张卡面同时出现在 w_* 和某把 gw_* 上，玩家在武器库里会看到两把不同名武器用同一张图）；且 w_* 的自造名与官方立绘内容不符（「训练长剑」配一把华丽的骑士剑）。
适用：作为**过渡止血**可以，作为终局不干净。

**方向 B · 把 gw_* 也降级成程序化卡面**
做法：弃用 718 张 webp，全列表统一用矢量剪影。
代价：直接与用户裁定相反（原话「都接入了全套武器，却还是用的简陋贴图」——他要的是**升上去**不是拉下来）；718 张已归档素材作废。
**不推荐**，列出来只为闭合选项空间。

**方向 C · 把首批 20 把换成目录武器（推荐）**
做法：20 把 w_* 退役为**目录武器的定位映射**——通用 4 把 → 目录里 Common/Rare 档同类型官方武器；8 职业 × 2 把 → 按 `classId` 的兵种/王国归属在目录里选同类型同稀有度的官方武器；存档 `unlockedWeapons` / `equippedWeapon` / `weaponTempering` 建 `w_* → gw_*` 迁移表。
收益：**一套贴图、一套稀有度口径（RARITY 双表合并，见 `heroScreen.ts:59-66` 与 `:644-654` 两张映射表）、攻甲血魔与词缀字段现成（718/718 有属性、710 把有词缀）、剪影兜底问题自动消失、H-4 的分母也自然变成一个口径**。
代价：20 条映射需人工裁定（要保住"职业毕业武器"的手感）；20 个手写 `SkillPrototype`（`weapons.ts:49+`）作废，改用目录 `spellId` 已编译原型；天赋条件 `selfStatIfWeapon` 依赖 `weaponType`，映射时要保证类型不变（`weapons.ts:33-37` 的注释已点明这层依赖）；`STARTER_WEAPON_ID` 与 demo 档淬炼种子需同步（`demo.ts:106`）。

**推荐路径**：阶段 B 先做 **A0 止血**（两处一行级：补 `WEAPON_ICONS` 的 mace/tome/shield/ring 四键消掉 7/20 错剪影；把程序化剪影与官方卡面**套进同一张卡框**——同底色、同描边、同 1:1 尺寸，让两套美术至少在同一个框里），再按方向 C 立一个独立批次做 id 迁移。A0 与 C 不冲突，A0 的卡框是 C 完成后仍要用的。

### 五问自查

1. **3 秒问题**：一半过关。三秒内能看出"这是我的主角页"（左侧 2/3 屏高的立绘 + 名字够强），看不出**下一步该点哪**：整页没有一个主行动按钮，视觉最强的是立绘和顶栏货币；真正的养成入口是两个灰色 `secondary`（「武器库 1」「武器图鉴」）和一个 `ghost`（「选择职业」），三者都排在分区右上角，权重比它们下面的说明小字还低。
2. **信息主次**：颠倒。玩家此刻关心的是「我多强」「我能变多强」「下一步练什么」。第一个被四个无标签数字（9/15/36/17）敷衍，而且这四个数还不含武器与淬炼（H-6）；第二个的主场地——38 职业——在首屏没有身影，标题占了位子但内容换成了特质（H-7）；第三个只有天赋路径那一行给了"还差多少"，武器和职业都不说差什么。
3. **视觉语言**：与全局暗金体系基本同源（卡面框/菱形档位/衬线数字/稀有度描边都在），**唯一的破口就是武器美术双轨**（H-3）：一边是透明底单色矢量，一边是满幅彩绘 webp，同一个 4 列网格里上下相邻。另外武器 slab 的 plate 把官方卡面缩到 120px 并保留其自带底色，与旁边程序化剪影"撑满整框"的画法不是一种构图（`hero-slab-catalog-weapon.png` vs `hero-default.png`）。
4. **操作路径**：核心路径全是断头路。**换武器 0 步可达**（按钮在弹层外，H-2）；**看第 9~20 把武器 0 步可达**（列表不可滚，H-1）；淬炼在英雄页没有任何入口（见 `06-forge.md` F-3），但材料库弹层明写「去向：英雄页武器淬炼」（`gameMain.ts:165`）；换职业要先猜到右上角 ghost 按钮；图鉴一点就跳出游戏（H-10）。唯一顺畅的是天赋改配（点档位 → 开树 → 点格子，有 toast 有取消）。
5. **极端态**：逐条实跑——
 - **未装备武器**：`renderSlab()` 有专门分支「未装备武器 / 去武器库选择一把」（`heroScreen.ts:745-752`），文案是设计过的；但那句"去武器库"指向的正是 H-1/H-2 两个坏掉的入口。
 - **无职业（新档）**：`careerName` 显「无职业」、天赋路径显单节点「待解锁 / 装备职业后点亮天赋」、特质板整块 `hidden`（`:500-506`）——这一态是设计过的。
 - **锁态武器**：剪影灰度 + 右下角 9px 锁图标 + 按钮「未解锁」（按钮在视口外，等于只有那个 9px 锁图标在承担全部信息量）；`hero-vault-detail-locked.png` 里法术数值仍是可点的高亮按钮，玩家会以为这把武器已经在生效。
 - **目录武器已锻造**：混排 + 来源自相矛盾（H-3/H-9）。
 - **满配天赋 / 满级职业**：`nextReward` 有「天赋已全部解锁」分支（`:318`），设计过。
 - **淬炼已有等级**：演示档起始武器已是淬炼 3 级，**页面上零显示**——既不在武器卡上，也不在详情里，也不在四维里（H-6 + F-3）。
