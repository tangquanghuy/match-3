### 重设计提案 · UX-5 活动商店独立页

#### A. 路由建议

| 项 | 建议 | 理由 |
|---|---|---|
| 路由 | **`#shop/<typeId>`**（六个活动各一页），裸 `#shop` 落"上次看过的那家店"，无记录时落入侵 | 与 `#events/<typeId>` 平级而非嵌套（`#events/<typeId>/shop` 会让返回栈变两层，而玩家的心理模型是"活动"和"商店"两个地方） |
| 屏名 | `screen.ts:10-11` 的 `ScreenName` 加 `'eventShop'`；`gameMain.ts:62-64` 注册 `eventShop: new EventShopScreen()`；`gameMain.ts:75-77` 页标题「活 动 商 店」 | 沿用现有屏注册机制，零新基建 |
| 页 CSS | `pageCss.ts:23` 的 `events: { css: liveCss }` 复用同一份 `liveCss`（商店样式已在 `live.css:103-120`，搬进新屏后就地扩写） | 商店与活动页同一套视觉语言，不该分家 |
| 返回 | 页内左上角「← 入侵周」回 `#events/<typeId>`；顶部页签行保留（可在六家店之间横切，不用退回去再进） | 玩家的真实动作是"逛完这家看那家"，不是"退出去再进" |

#### B. 入口位置（三处，缺一不可）


- ② 的入口条是**吸底常驻**，不随面板内滚动消失——这是 S-1 的最小修法：即使商店搬走了，活动页上也必须有一个永远看得见的"我有多少币 / 去哪花"。
- ③ 结算屏已经有活动推进行（`TASK-META §8.6`：「结算屏：素材行 + 活动玩法推进行 +『回到活动页』直达」），在代币入账那一行右侧挂「去商店」——玩家刚赚到币的那一秒是花币意愿最高的一秒。

布局规则七条：
1. **代币栏吸顶**。余额、产出速率、清零时刻、"清空这架还需多少/约几场"四件事常驻可见（修 S-4）。
2. **招牌位**：`stock === 1` 的货品（圣辉石/万能石类）单独提到第一屏，大图标 + 「★ 本周限 1」。这是每架货真正的钩子，现在它和 6 代币的普通钢锭长得一样（修 S-6）。
3. **图标优先、文字退位**：货品内容用「色点 + ×N」表达（特质石六色直接用 `STONE_COLOR_HEX`，钢锭七档用稀有度色，货币用顶栏图标）；`name` 只做包名，不再复读内容（修 S-2）。
4. **持有量与买后量同屏**：每件货显示「持有 N → 买后 N+X」。这是玩家判断"要不要买"的唯一依据，目前全链路缺失（他必须去顶栏材料库弹层才能查，见 `13-materials.md` MT-7）。
5. **三种态形态化，不靠透明度**：可买=实底金按钮；买不起=按钮换成「还差 N 枚 · 去打一场 ▸」（**可点，直接跳该活动出战**，把死路变动线）；售罄=卡面压暗 + 「本周已售罄」文字 + 「周一 0:00 补货」（修 S-3）。
6. **限量写成分数**：「本周剩 4 / 4」而不是「剩余 4」——分母让玩家知道这周总共能买几次。
7. **购买反馈三件套**：① 卡面上数字就地变化（持有量 +X、剩余 −1、代币 −N 飘字）；② toast 写全「已购入 初级石包 ×6（🔴×2 🔵×2 🟢×2）· 代币 72 → 64」；③ 若该素材有明确去向，toast 挂一个「去解锁特质 ▸」的跳转（修 S-7）。

#### D. 六活动独立代币池怎么在同一页表达

`TASK-UX §4` 已裁定"每活动独立代币池，互不通兑"。同页表达用**三层冗余**，任一层单独都能读出归属：

| 层 | 做法 |
|---|---|
| 页签层 | 六枚页签**各自带余额**：`⟨入侵周 🪙72⟩ ⟨突袭首领 🪙40⟩ …`。这一行同时回答"我在哪家店"和"哪家店我有钱"，不用切页就知道该去哪 |
| 代币栏层 | 代币名**带活动前缀**：「入侵代币」而不是「活动代币」；图标底色取该活动主题色（入侵紫红 / 突袭橙 / 塔青 / 阵营金 / 世界绿 / 试炼蓝），六色固定不复用 |
| 货品层 | 价格标签用同一主题色的 🪙 图标。玩家在两家店之间来回时，价格颜色变了 = 钱包换了 |

另加两条防误解：
- **不进顶栏**。六种代币若进顶栏钱包会把 5 项变 11 项（`chrome.ts:135-156`）；代币只在活动语境里存在，这也强化"互不通兑"的认知。
- **明说不通兑**。代币栏右侧一行小字：「各活动代币独立，不可互换」。这句话必须有——玩家默认同名货币是通用的（尤其当它们都叫"活动代币"、都是同一个金色圆点时，`live.css:108`）。

### 五问自查

1. **3 秒问题**：**不过关，因为三秒内根本看不到它**。商店在面板内部滚动条以下（S-1），玩家进活动页三秒内看到的是横幅+规则卡+状态区+里程碑，没有任何迹象表明还有一家店。就算滚到了，三秒内也读不出"这架的招牌货是哪件"——4~5 件货同一个灰盒子同一个字号（S-6）。唯一视觉最强的是右上角的金色代币数字，而那是余额不是行动。
2. **信息主次**：**颠倒**。玩家在商店里只关心三件事：这件我买不买得起、我还缺不缺、错过了会怎样。三件分别是：要点下去试（`poor` 不禁用，S-3）、页面不显示持有量（要去材料库弹层）、限量只写「剩余 N」不写刷新时刻（S-3/S-4）。而被写得最响的是**重复了一遍的货品名**（S-2）和一行英文装饰 `EVENT SHOP`（`live.css:106`，字距 .28em）。
3. **视觉语言**：**不成立**。整架 `[data-icon]` 计数 0，全部是圆角灰盒 + 一个金色价格数字；六档货价差 10 倍而外形完全一致；售罄/买不起/可买三态只有 `opacity` 三档（.38 / .75 / 1）。与宝箱页（1200px 主视觉 + 分池按钮配色）和图鉴页（稀有度色边 + 立绘）不是一个体系。UX-13 在这一块的表现是"连按钮都没有"——货品**本身**就是按钮（`eventsScreen.ts:93` 的 `<button class="ev-goods-item">`），所以屏幕上看不到任何"购买"字样。
4. **操作路径**：**能走通，但每一步都靠试**。买一件货：进活动页 → 面板内滚到底 → 点货品 → toast。四步里第二步不可发现、第三步没有确认（点一下直接扣款，`eventsScreen.ts:239-249` 无二次确认——对 60 代币的限量 1 件商品也是一点即买）、第四步不告诉你买到了什么（S-7）。断头路：想知道自己有多少初级火之石 → 商店内无入口；想赚代币 → 商店内无"去打一场"入口（买不起时是纯拦截）。
5. **极端态**：逐条实跑过——
   - **代币 0（新周首访）**：四件货全 `.poor`、**全部可点**，点了出「活动代币不足：需要 8，现有 0」。这一态是"恰好没崩"（S-3）。
   - **售罄**：有专门分支（`disabled` + `opacity:.38`，`eventsScreen.ts:93` / `live.css:119`），点不动——这一半是设计过的；但不写"售罄"、不写补货时间（S-3）。
   - **限量买到最后一件**：`stockLeft` 递减正确（探针 `剩余 4 → 售罄` 两态都截到），`buyEventGoods` 有 `SOLD_OUT` 错误码兜底（`systems/events.ts:buyEventGoods`）。系统层是严谨的，呈现层没跟上。
   - **5 件货的活动**：4 列网格掉行，第 5 件（最贵的传说钢锭）孤零零在第二行（S-6，截图 `shop-raidBoss-shelf.png`）。
   - **非轮值周（五个活动）**：商店**整块不存在**（探针 `goods:[]` ×5）。全开放裁定后这一态消失，但目前它意味着"六个商店里五个不存在"。
   - **纯货币货架（世界事件）**：四件全是黄金/灵魂/宝石/钥匙，顶栏钱包里有对应项——这一架是唯一"买了能在顶栏看到变化"的，反而衬出其他五架的素材入账完全不可见。
   - **跨周作废**：**无任何表现**。周切时 `ensureEventWeek` 直接重建周实例（`systems/events.ts:ensureEventWeek`），剩余代币静默清零，没有提前警告、没有事后告知。与 `01-map.md` M-10 的"进贡溢出静默丢失"是同一类问题。
