### 决策信息充分性（本页核心问题轴）

玩家在本页要做两个决策：**这张卡要不要**（三轮，不可回退）与**谁站 1 号位**（A-1 目前做不到）。下表逐项列出缺什么、数据在不在手。

| 决策需要的字段 | 现在有吗 | 数据层是否现成 | 取法 |
|---|---|---|---|
| 攻击 / 护甲 / 生命 / 魔力（满配等级下的值） | ❌ | ✅ | `troopStatsAtLevel(troop, arenaDraftLevel(o.rarityIdx))`（`systems/troopProgress.ts`；`arenaDraftLevel` 已在本屏 import） |
| 技能名 | ❌ | ✅ | `troop.spell.name`（`getTroopById` 已在 `arenaScreen.ts:218` 取到） |
| 技能全文（+ 公式求值） | ❌ | ✅ | `troop.spell.description` + `shell/spellText.ts:renderSpell(desc, magic)`（英雄页/图鉴已是成品） |
| 耗蓝 | ✅ | — | `troop.manaCost`（`:222`） |
| 法力色 | ✅ | — | `gemSvg(troop.manaColors)`（`:222`） |
| 种族 / 特质 | ❌ | ✅ | `troop.type` / `troop.traits`（阵营协同与"3 人队能不能互补"要靠它） |
| **这三张与已锁定卡的法力色互补情况** | ❌ | ✅ | 已锁定卡在 `draft.picked`，颜色取并集即可——3 人队最怕三张卡抢同一色 |
| 对手三战的阵容 | ❌ | ✅（种子化） | `arena.ts` 的 draft seed + `pickEnemies`，出战前可算（A-4） |
| 站位与「队首吃骷髅」的实际差别 | 文案有、操作没有 | — | A-1 |

结论：**本页现在无法做出任何有依据的选择**。三轮抽卡实际退化为"按稀有度点最高的那张"，站位决策被一行 CSS 关掉。

#### P0 · A-3：本届战报（结算落点）

竞技场不必新建结算屏，但**必须有痕迹**。两选一：
- **方案 A（推荐）**：复用 `#result` 屏，`sourceLabel = 'ARENA RUN'`，明细行给「胜场奖励」「战斗内收集」两类；`returnHash = '#arena'` 让「返回」直达本页。改动面只在 `battleLauncher.ts:114-132`。

两者都要解决同一件事：**打满 3 胜的那一刻要有一个配得上 12,000 金的画面**，而不是一行 toast。

1. **3 秒问题**：**报名页过关，抽卡页与连战页不过关**。报名页三秒内能读出「现开赛 / 3 轮抽卡 / 3 人 / 连战 3 场」并看到唯一的绿色主按钮，这一页是全仓少数信息架构清楚的页面。抽卡页三秒内看到三张漂亮大卡，但**读不出该按什么标准选**（A-2）；连战页三秒内看不出"我现在该干什么"——主按钮「开始第 1 场」在右下角，而左栏那句「▲▼ 调整站位」把注意力引向一组点不动的按钮（A-1）。
2. **信息主次**：**抽卡页颠倒**。玩家此刻唯一关心的是"这张卡强不强"，而卡面把 62% 的面积给了立绘、把文字位给了"临时卡"这种注脚（三张卡都一样，零信息量）。连战页同理：「主角不出战 · 本场卡组将在赛毕清除」这句已经在报名页说过的话，在连战页又用一整条 `.battle-note` 横幅重复一遍（`arenaScreen.ts:137`），而真正该被强调的"对手是什么"一个字都没有（A-4）。
3. **视觉语言**：**本页是与全局体系最贴合的一页**（暗金框 + 稀有度描边 + 菱钉主按钮 + 罗马数字战次），`arena.css` 是按屏注入追加在全局之后的（`pageCss.ts:22`），所以它的覆盖是可控的。两处破口：① draft 卡自带一套 `--rarity-*` 变量（`arena.css:252-254`），与 `screens.css:1271-1276` 的 `--r-*`、`troop.css:170-171` 的 `--rc` 是三套稀有度色板（见 `DESIGN-SYSTEM.md` DS-9）；② ▲▼ 按钮用 22×16px 的深色小方块（`arena.css:472-479`），与全局 44px 触控口径差一个量级——就算修好 `pointer-events` 也依然难点。
4. **操作路径**：**主路径 5 步通，两条支路断**。通的：报名 → 选卡 ×3 → 出战 → 打完自动回本页。断的：**换站位（A-1，0% 可用）**；点三步指示器回看奖表（A-8，无绑定）；打完想看战报（A-3，无落点）。另有一条半通：弃赛能走完，但拦在一个系统 `confirm()` 后面（A-5）。
5. **极端态**：逐条实跑过——
   - **本周免费票已用**：有分支（`renderSignup` 把 `#ticketCopy`/`#feeCopy` 切成「本周免费已用」/「宝石 150」），但按钮始终 `disabled = false`（`arenaScreen.ts:191`），宝石不足时要点下去才由网关拒绝（与 `08-chests.md` CH-4 同一个"按钮永远亮着"的家族）。
   - **中途退出再回来**：`render()` 按 `activeDraft.stage` 恢复到 draft/battle 阶段（`:166-174`），这一态是设计过的；但 `this.order` 是屏实例字段，切屏即丢，回来后站位重置为 `draft.picked` 原序（`:277`）——玩家精心排的站位在切页后静默复原（因为 A-1 现在根本排不了，这一条暂时不可见，修好 A-1 后会立刻暴露）。
   - **弃赛后**：toast 报「弃赛收官：N 胜 · 黄金 +X」并回报名页，`this.order = []`（`:381`），状态干净。
   - **draft 卡取不到 troop**：`getTroopById` 返回空时模板返回 `''`（`:220`），会静默少一张卡而不是报错——"恰好没崩"，但玩家会看到 2 选 1。
