### 重设计提案

#### P0 · T-1 / T-2 / T-3 / T-4：浏览层重做（线框）

根因是一条：**"按王国分组"被当成了唯一的信息架构**，而它同时制造了 75% 的空槽、42 个吸顶条、以及和王国筛选器的功能重复。提案是把分组降级为"分组模式之一"，默认走密排网格，并把排序提到和筛选同级。

```
┌─ 我的收藏 ─────────────────── 已拥有 85 / 1,798  (4.7%) ──┐
│ ▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  4.7%              │
├───────────────────────────────────────────────────────────┤
│ ⟨已拥有 85⟩ ⟨全部 1798⟩   ← 两个真 tab，带计数，切换后回顶   │
│                                                            │
│ 品质  全部27 普通9 非普6 稀有4 超稀有3 史诗1 传说0          │← chip 带"我有几张"
│ 魔法  ●红12 ●绿8 ●蓝21 ●黄9 ●紫14 ●棕21    [✕清除]        │
│ 种族 ▾  王国 ▾  🔍搜索（名字/法术/特质）                    │
│ ── 排序 ▾ [等级↓] ────────────── 分组 ▾ [不分组]  ─────── │← 新增两个控件
│                                                            │
│ 当前筛选： [传说 ✕] [红 ✕] [野兽 ✕]        匹配 7 支        │← 筛选摘要，单条可撤
├───────────────────────────────────────────────────────────┤
│ ┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐         │
│ │卡面││卡面││卡面││卡面││卡面││卡面││卡面││卡面│  ← 密排，  │
│ │Lv9 ││Lv9 ││Lv1 ││Lv1 ││Lv1 ││Lv1 ││Lv1 ││Lv1 │    不留空槽│
│ │⚔5🛡3││⚔0🛡8││... │└────┘└────┘└────┘└────┘└────┘         │

└───────────────────────────────────────────────────────────┘
```

规则五条：
1. **默认不分组**，密排 8 列 → 85 张卡从 25.5 屏压到 ≈11 行 / 2.5 屏。王国分组保留为「分组 ▾」的一个选项，且与王国筛选器互斥（选了单个王国就不再画条）。
2. **「全部」态必须分段渲染**：按当前排序切成 200 张一段，滚到段尾再追加（或直接虚拟滚动）。1798 张一次性 38,073 节点是这一页最大的性能与节奏问题。
3. **排序控件与筛选同级**：等级 ↑↓ / 稀有度 ↑↓ / 攻击 / 生命 / 副本数 / 收藏时间 / 图鉴号。默认「等级↓」，直接回答"我该练谁"。
4. **任何筛选/排序/切 tab 之后 `scrollTop = 0`**，无例外。
5. **筛选摘要 chip 行**常驻在结果计数旁边，每条带 ✕；「重置筛选」同时重置 tab。

#### P0 · T-5：详情页出口（线框）

底部控制条从"←  卡名 · 已拥有 3 张  →"改成三段，把"用它"提到主行动位：

```
 ┌──────────────────────────────────────────────────────────┐
 │  ←  上一张          食人魔 · 已拥有 3 张          下一张 → │← 箭头只在"当前列表集合"内走
 ├──────────────────────────────────────────────────────────┤
 │      【 编入队伍 ▾ 】        ← 主行动，金色实底           │
 │       先锋队 1号位 / 2号位 / 3号位 / 4号位（下拉直接选槽） │
 └──────────────────────────────────────────────────────────┘
```
- 箭头遍历的集合 = **进详情时那份筛选后的列表**，不是 `TROOPS` 全表；这样"在传说红野兽里逐张翻"才成立，也不会掉进未获得卡。
- 已在队伍中的卡，按钮变「已在先锋队 2 号位 · 卸下」。
- 未获得的卡，这个位置换成「**获取途径**」：该王国的任务链 / 哪种宝箱 / 竞技场奖励——目前这块信息在详情页完全缺席（见五问第 5 条）。

#### P0 · T-4 配套：筛选反馈

筛选生效的瞬间给三件事：列表回顶、结果计数做一次数字变化的高亮、若结果为 0 则在空态里点名是哪个条件最先把结果筛没的（服务端式逐条回退计算，例如"去掉『王国=阿达纳』可得 7 支"），并给一键放宽按钮。

### 五问自查

1. **3 秒问题**：**不过关**。三秒内能读出"这是我的收藏、85/1798、4.7%"——页头这块是做对的。读不出的是"下一步点哪"。全屏视觉最强的是右上角那枚金框实底按钮「查看详情 →」，而它是这一屏**最不该点**的东西：它把你送到上一次浏览的那张卡（空收藏时送到一张 `001/000` 的破卡，T-13）。真正的入口是 85 张长得一样的小卡，没有任何一张被推荐、被标"可升级"、被标"新获得"。筛选区七个控件横排一行、全是同一种低对比灰字（`troop.css:180` 里 `.collection-filter` 基色 `#887d8e`），三秒内看不出哪个是主筛选。

2. **信息主次**：**颠倒**。玩家此刻关心三件事——"我有什么强卡""这张卡值不值得投""我缺哪些"。第一件事需要的数值在卡面上一个都没有（T-8）；第二件事需要的余额/收益在详情页只写了代价（T-10、T-11）；第三件事需要的"缺哪些"在"全部"态被 1713 张灰卡淹掉（T-2）。被排得最响的反而是注脚：42 个王国名各自占一整条吸顶条（还是半透明的，T-6）、页头「THE BESTIARY · 1,798 CARDS」这行英文装饰、以及底部那句重复了两遍的「点击卡片查看详情 · 未获得的部队也可查看图鉴」（`troopScreen.ts:158` 和 `:162` 各写了一次）。

3. **视觉语言**：**列表层合格，详情层破功**。列表的卡面（暗底 + 稀有度色边 + 法力宝石角标 + 立绘）是和战斗卡同源的，这套是成立的；问题是稀有度只有 3px 且无图例（T-7）。详情层有两处明显脱离体系：一是**法术描述用的是米白/羊皮纸底的浅色块**（截图 `troop-14`/`troop-21` 里它是全屏最亮的元素，亮度远超「提升等级」这个主行动按钮）——一段静态说明文字抢走了全屏第一视觉；二是「提升等级」按钮是暗绿系，和全局暗金按钮体系不是一套（UX-13 的具体案例）。另外分解这种破坏性操作套用了成长区的同一个 class（T-16），危险级别在视觉上完全没有表达。

4. **操作路径**：**主路径通，周边全是断头路**。通的：`#troop` → 点卡 → 详情 → 升级/解特质，3 步；深链 `#troop/<id>` 直达详情也是通的（截图 `troop-23`）。断的：详情 → 用这张卡（无出口，T-5）；详情 → 下一张（掉进未获得卡，T-5/T-14）；详情 → 返回图鉴（位置丢失，T-9）；筛选 → 结果（滚动留在原地，T-4）；空收藏 → 去哪弄卡（无入口，T-12）；特质代价 → 我有多少石头（要去另一个页面的弹层，T-10）。

5. **极端态**：逐条实跑过——
   - **空收藏（0 张）**：不崩，但**没有设计过**。文案是错的（叫你改筛选，而你没设筛选）、下方 500px 纯黑、无 CTA、「查看详情」还能点进一张 `001 / 000` 的空白卡（T-12、T-13，截图 `troop-24`/`troop-26`）。
   - **未获得卡**：列表侧设计过（去色 `grayscale(.9) brightness(.42)` + `?` 遮罩 + "尚未获得"），**详情侧没设计过**——`.unowned` 类挂了但零样式，卡面全彩（T-14）。文案层反而做得挺细：「获得该部队后可提升等级」「获得后可解锁」「尚未获得 · 图鉴资料仅供参考」、分解块整块隐藏（探针 `未获得态文案` + `decomposeHidden: true`），这几条是设计过的。缺的是**最关键的一条：怎么才能获得**——整个未获得态没有任何获取途径提示。
   - **筛选 0 结果**：有专门分支但复用了错误文案，且不指认是哪个条件（T-12）。
   - **升阶受阻**：设计过——按钮文字从「升一阶」变「副本不足」并置灰，caption 写「持有 3 张 · 可用副本 2 张」，宝石格 2/5 点亮（`troopScreen.ts:484-503`）。缺收益说明（T-10）。
   - **等级满 / 特质全解**：设计过——「已达稀有度上限 · 升阶可提升」、「特质全解锁」/「无更多特质」、三特质卡的「该部队没有第三个特质」都有专门分支（`troopScreen.ts:428-431,467-472,451`）。
   - **灵魂/黄金不足**：**没有前置拦截**。`#upgrade` 的 disabled 只看"是否拥有 + 是否满级"（`troopScreen.ts:434-435`），`#unlock` 只看"是否拥有 + 有无下一槽"（`:474-481`）——都不看余额。按钮永远亮着，余额不足走网关 `isFailure` → toast（`troopProgress.ts:97,155-162` 的 `spend`/`spendMaterials`）。这一态是"恰好没崩"，不是设计过的。
   - **分解到只剩本体**：设计过——`copies < 1` 时按钮置灰（`troopScreen.ts:512`），`locked` 时也置灰并显示「已锁定 · 防止误分解」。
   - **1798 张全量**：见 T-2，`38073` 节点 / `52258px`，图片来不及解码时页面是一片空黑框（截图 `troop-25`）。这一态"没崩"，但浏览体验不成立。
