# 技能编译器 · 基础技能调研报告

> 数据来源：`src/data/troops.json`（1798 个兵种技能），统计脚本 `scripts/_analyze_simple_skills.mjs`。
> 目的：为"技能文本 → 可执行技能原型"的编译器划定**第一批要做的效果类型**，只做调研，不含实现。

## 一、结论速览

- 技能总数 **1798**。
- **直接伤害覆盖最大：1043 条（58%）**，其中指定单体 590、群体 213、溅射/多目标 104、随机单体 95。
- 宝石操作合计约 40%（创造 348 / 爆破摧毁 314 / 转化 173）。
- 增益合计约 25%（治疗 146 / 护甲 124 / 攻击 99 / 魔法 65 / 法力 53）。
- 额外回合 161（9%）、召唤 141（7.8%）。
- 净化（驱散己方负面）30，消除敌方正面增益仅 9（很少，可后置）。

> 关键事实：绝大多数技能是"**主效果 + 若干次要修饰/条件**"的结构。只要把主效果编译对，配合"复杂条件段安全忽略"的回退策略，就能让 **1500+ 兵种放技能时产生真实战斗效果**。

## 三、明确排除在第一批之外的（本期作为"次要段忽略"或整体回退）

这些是导致技能"部分识别"的主因，本期不编译，主效果照常生效：

- **条件判断**：`如果敌人身亡`、`如果是恶魔/高塔/Boss`、`如果攻击力更高`
- **概率**：`X% 的几率…`
- **数值增强**：`伤害值因…而增强`、二级修饰 `[xN]`/`[N:M]` 的战场结算
- **倍率**：`造成双倍/三倍伤害`、`基于晋升稀有度 3–5 倍`
- **资源转移**：`窃取`、`耗尽法力`、`转化成攻击力`
- **GoW 特色机制**：`下潜`、`吞噬`、`猎人标记`、`魅惑`、`打回末位`

## 四、编译策略（供设计阶段参考）

1. **不重新切分中文文本做数值提取**——数值一律用已解析好的 `meta.scalings`（构建期已产出，见 battle-skill-system 需求 2），编译器只负责"识别效果类型 + 目标 + 绑定第几个 scaling"。
2. **逐句分段**：按句号/逗号切子句，逐句匹配效果模板；命中生成效果段，未命中（或含复杂词）安全忽略。
3. **回退**：整条技能一个效果段都识别不出 → 回退"仅扣法力"（引擎已支持，battle-skill-system 需求 11.4）。
4. **产出**：编译结果 `SkillPrototype` 写入 `troops.json`（或旁挂表），`castSkill` 按原型执行。
5. **覆盖率看板**：脚本持续报告"有真实效果 / 完全识别 / 回退"三档比例。

## 五、预期覆盖

- **至少产生一个真实效果段**：约 **84.6%（1522 条）**（逐句分段策略实测）。
- **完全识别（所有实质子句都命中）**：约 10.7%——这个比例低是正常的，因为大量技能带"增强/条件"尾巴；这些在本期作为次要段忽略，不影响主效果与可玩性。
