# 敌人组装器 v2 与运行时提示词盲审

日期：2026-10-25。本记录对应继续修复候选覆盖、让子 agent 在盲写战斗块之外审查提示词可执行性的要求。整版状态见 [STATUS](../tasks/active/STATUS.md)。

## 修复原因与实现

上一轮只解除立绘与颜色绑定，原六份反例仍为整队 1/6、单体 7/16。机械候选在进入效果及权重审查前，因源模板的主职责、档位和完整配色交集过窄而归零；另有同档同形态缺同视觉职责图片的情况。修改提示词让 AI 绕开这些组合，会把实现缺口转嫁给输入。

新 generation v2 按源主职责、原始稀有度和档位选择完整原生主动及有效有序特质，将请求的实例充能配色独立绑定。费用、伤害公式、技能内部固定的造石／转色颜色、目标、条件和概率保留。供魔和循环档案按实例配色检查，实际引擎的消除回蓝也使用实例配色。不同实例配色参与来源与学习身份；同一集合的不同排列先统一顺序，避免身份相同而第一色行为不同。

立绘优先同 rank/form/role，缺同职责图片时回退到同 rank/form 的其他视觉职责图片。机械职责继续来自请求对应的源主职责，不借图片标签串池；档位和形态仍保留真实资源约束。运行时 AI 的五字段接口保持不变，具体技能效果、特质及组合权重由程序承担。

旧 generation v1、带旧画像颜色查询的生成档、无 generation 档分别保留原选择分支和完整结果校验。三个修改前冻结夹具原样保存，新增策略不迁移旧结果。源配方签名按固定目录对象缓存，实例配色另行参与组装签名。

## 独立复核与供魔边界

Noether 独立复核先运行 43 项测试，确认候选覆盖、立绘与机械职责、冻结旧档及配方签名缓存的处理成立；同时复现颜色顺序与供魔循环两处缺口。颜色顺序由主线程修正。随后按明确文件范围实现 v2 供给关系检查，旧 v1 档案形状与判定保留。

v2 记录每名成员的实际用色、可执行分支中的造色、棋盘法力收集及直接供魔受益对象；闭合供给链上同时存在吞噬／处决与显式额外回合，或低费群控与显式额外回合，才进入团队组合拒绝。普通颜色相交不单独判错，互斥分支、无效供魔、无关的自回蓝成员不拼成一条虚假的循环。

这属于风险准入，未宣称证明无限循环。数量、费用回收、前排截流及棋盘概率仍影响能否持续；条件供魔、四连间接续回合、复杂复合路径仍需战斗行为验证。

## 提示词盲审

第一位盲审者只读旧提示词，先生成六份战斗块，再写意见。指出字节上限无实际操作意义、触发判断顺序不合理、个体阶级与整队出场规则容易混淆，以及部分程序说明占用注意力。已移除 AI 提示词中的 32 KiB、内部源标识及算法说明，改按触发、配置、输出等待、接收战报排列任务；队形只确定一次，随从不递归添加随从。

第二位盲审者只读冻结修订稿，先保存六份新战斗回复和三个流程探针，再评价。指出颜色互异／顺序、相近职责、战斗事实与后续叙事等歧义。随后明确颜色互异且顺序无关，增加三组近似职责的简短选择依据，并允许人物反应及后续事件。最终稿由同一审阅者复核，确认三处改善；原盲样与其实际输入的冻结提示词保持不变，未将最终稿冒称为原始生成依据。

字节限制保留在解析器及工程文档中。EJS 继续在发送前执行，已测开启时仅输出规则正文、关闭或屏蔽时为空。AI 只负责配置敌人与战报叙事，程序负责身份绑定、历史去重、选型、组装及结算。JSON 标记、字段、枚举与数组对应正文顺序属于必要输出契约，继续保留。

人数骰语义、传奇具体队形、区域等级缺省、取消遭遇后旧入口失效条件仍属产品待决项。本轮保留现有规则，未代用户改变。
