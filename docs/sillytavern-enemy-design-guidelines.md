# 敌人组装设计准则

日期：2026-10-25。依据：[技能分布审计快照](sillytavern-enemy-skill-distribution-20261025.md)。本文规定本轮架构与验收口径；核心与策略模块并行交付，最终实现须按文末清单独立复核。本文修订本身未执行新一轮结构覆盖、机制行为或平衡验收，历史报告的比例不代表本轮通过率。

## 1. 主职责与技能能力分开

每名敌人只有一个主职责。AI 选择 `role` 及遭遇基础信息；程序在该职责的源模板池中生成完整战法。完整主动和特质另有可重叠的能力标签：带直接伤害不自动归到 Striker，伤害采用魔力系数也不自动归到 Mage。供魔可以同时伤害和转色，辅助可以同时伤害和治疗，坦克可以同时防护和反击。

产品规则分为三层：

1. **源主职责**：完整主动模板按源单位 `role` 固定分池。classified 请求的 `role` 与候选源职责一致；副效果和后配特质均不改变池归属。源职责来自原角色整套配置，替换特质后仍需核对主任务的实际证据。
2. **能力档案**：保留伤害、供魔、棋盘操作、治疗、控制等标签，以及真实费用、公式、数量、对象、条件和互斥分支。标签用于池内排序、机制准入和行为验收，不产生第二个主职责。
3. **编队功能**：根据实际受益对象、队伍用色、进攻来源和循环风险检查完整阵容。增加一个能力标签并不增加一个编队职责位置。

例如 Generator 源模板同时造成伤害并转红石，仍留在供魔池；检查红色能否供给实际队友、棋盘资源是否存在。Striker 配上供魔特质，仍属于输出主职责。源职责的任务若由原特质承担，替换后要保留相应收益链；保留同名标签或一个无关自保效果不足以证明主任务成立。

预览的主职责展示取 `activeDesign.design.role`。旧 `signature.roles` 即使含多个效果兼容项，也只作为兼容元数据；实际技能能力继续显示 effects、完整技能描述和特质说明。

## 2. 源职责固定分池，池内加权选择完整战法

下表描述源职责的作战主题和复核重点，不是根据一条效果重新判职的规则。源分类中存在边界样本时，保留可追溯来源，交给分类证据与行为检查，不在随机生成时自动改职。

| 主职责 | 作战主题与复核重点 | 常见副能力与边界 |
|---|---|---|
| Striker 输出 | 持续或集中制造进攻压力；检查伤害对象、可执行路径和费用收益 | 转色、供魔、自保、削弱；附带伤害的其他职责仍留在原池 |
| Mage 法师 | 保留源法师模板的完整战法，检查伤害形态及施法收益 | 造石、控制、供魔；正魔力系数只说明公式 |
| Assassin 刺客 | 保留源刺客的目标选择与击杀压力，检查概率、前提及应对窗口 | 真实伤害、后排打击、削弱；全体真实伤害不自动证明刺客定位 |
| Warrior 战士 | 检查队首攻击、骷髅、攻击成长或源模板已有的进攻链 | 主动伤害、自我增益；不强制每个模板同时具备直接伤害和加攻 |
| Defender 坦克 | 检查实际站位、防护对象和承伤机制 | 伤害、反击、治疗、供魔；仅有治疗或一条护甲标签不足以证明能承担前排压力 |
| Generator 供魔 | 检查直接法力、可利用产色和队伍施法链 | 伤害、转色、爆破、增益；棋盘收集的颜色和数量以真实结算为准 |
| Support 辅助 | 检查收益实际到达存活队友，区分自身收益和对队友的收益 | 治疗、净化、防护、召唤、供魔；仅自疗不证明支援收益 |
| Warlock 术士 | 检查削弱、控制、驱散的目标、覆盖和持续 | 伤害、棋盘操作、自保；负面效果的出现不决定源主职责 |
| Warmaster 统帅 | 检查队伍攻击、骷髅或其他已证明的团队协同链 | 造石、转色、伤害、召唤；单独召唤或仅自我加攻不等于团队统帅收益 |

选择顺序：

1. generation v2 先按源主职责固定候选池，再筛原始稀有度、档位及机制可用性，不用源充能配色缩窄候选。将请求的实例充能配色规范排序后绑定，并用该实例配色检查供魔关系；技能内部固定的造石、转色等颜色保留。真实立绘优先按 rank/form/role 匹配，缺少同职责图片时使用同 rank/form 的其他视觉职责图片；机械职责仍由源主职责保证，法力颜色不参与选图。
2. 在池内提取完整主动档案，以机制组合、伤害形态、费用区间、条件复杂度等形成战法分组。固定 `spellId` 的同一主动因多个来源或外观出现时，按 unique spell 去重，避免样本重复放大战法权重；来源身份、原生特质和底板仍可追溯。
3. 先选择战法组，再选择组内完整主动。权重由程序内部结合 `role` 偏好、机制复杂度及已知队伍上下文计算。原库出现频率、外观数量、同一主动可配的特质组合数均不应直接放大主动的入选机会。
4. 为选中的完整主动搭配实际可用的特质，限制槽位、来源稀有度、重复 code 和上下文依赖。替换前后检查源主任务；特质既可补强主任务也可增加副能力，效果覆盖不作为跨职责借用许可。
5. 对最终主动、特质及整个编队分别执行强机制与组合限制。有候选缺口就记录原因；保留请求的主职责和限制，不自动串到其他职责或特殊池。
6. 种子用于复现，换种子可换战法；保存实际蓝图及影响选择的上下文，恢复时核对版本、参数和完整结果。选图、战法选择、四维浮动与战斗棋盘使用各自的确定性输入。

旧审阅曾发现黄紫／杂兵／人形、请求 Striker、伤害＋转色、种子 1 选到 Generator 报丧女妖 6053；此例已纳入职责串池回归：新生成按源职责分池，Generator 可保留伤害＋转色，Striker 不借用该来源；定向复验与独立审阅结果见 [当前状态](../tasks/active/STATUS.md)。旧 `native` 存档的确定性另行验证，不因新池规则悄然迁移旧结果。

### 职责文案给核心维护者的建议

- 将旧角色说明中的“有 damage 即输出”“正魔力缩放即法师”“真实伤害即刺客”收回到能力档案，避免提示词或诊断继续暗示效果判职。
- Support 的说明与证据应明确自身／盟友对象；Defender 的说明与证据应明确承伤位置和防护对象。只保留 heal、barrier 或 armor 的词面，可能漏掉原特质移除造成的主任务丢失。
- Warrior 的描述不宜写成所有模板都须同时伤害和加攻；Warmaster 的描述也不宜压缩成单一 teamAttack 标签。按源池保持分类，再检查原模板实际依赖的攻击、骷髅或团队协同链。
- 供魔说明保留“棋盘资源决定实际收益”，并区分摧毁／爆破与移除、产骷髅与产六色法力资源。团队上下文应影响收益核验，不能把固定颜色改成万能供魔。

## 3. 机制复杂度与强度分别限制

[分布审计](sillytavern-enemy-skill-distribution-20261025.md)中的历史样本显示，多数完整主动集中在少量机制家族；这些统计用于描述候选库，不直接证明抽取权重或强度平衡。

普通池优先选择易读、主题集中的完整战法；复杂机制按内部规则降低权重或限制准入。复杂度按实际可执行路径统计，互斥分支分别保留，不把不同分支拼成一次施法的必得收益。段数、effects 标签数、机制家族数与强度分别记录；依赖链的归并仍保留原始参数和可追溯依据。

普通池对低原始稀有度和低档位的强机制设限，吞噬、处决、敌方强制变形、直接额外回合等不因原库已有或附带概率就自动准入。限制读取完整主动与最终有效特质，也检查跨成员形成的组合。档位与原始稀有度分别报告；提高等级、难度或参考战力上限不绕过准入规则。

特殊池保留有明确主题的完整模板，独立记录准入原因及行为证据；分类编译成功不等于自动开放普通随机生成。普通池失败也不自动切换特殊池。特殊池仍受派生可用性、未知机制及组合限制约束。

具体复杂度上限、强机制计数和权重系数由内部策略版本定义，待分类行为和模拟结果校准；本文不新增玩家或 AI 的数值旋钮。等级、难度和生命倍率沿用既有边界，动态难度另行安排。

每个原始稀有度及酒馆档位达到至少 90% 是待验证的覆盖目标。报告保留全量分母，普通池和有证据的特殊池并集按源条目去重；同时报告普通池自身规模、独立主动模板数量与失败原因。结构覆盖、生成准入覆盖、行为证据覆盖和平衡结果分开出具，历史结构报告不作新规则或行为平衡的通过证明。

## 4. 强力效果与组合限制

所有概率、条件、费用和负面代价均属于机制本体，挑选时一起保留。低概率效果不自动等同低风险；自供魔和额外回合可能使它被连续尝试。

| 机制／组合 | 选择与验收要求 |
|---|---|
| 吞噬 | 区分敌方吞噬与献祭己方；记录目标、概率、概率加成、免疫与属性转移。普通杂兵池零权重；特殊模板验证前提与应对方式 |
| 处决／即死 | 区分无条件、目标已有状态、生命门槛及击杀后连杀；不与普通伤害只按段数比较 |
| 额外回合 | 分别标记主动直接授予、概率授予、条件授予，以及宝石操作形成四连后的间接续回合。纯主动 extraTurn 词的出现率不是全部循环率 |
| 自供魔／团队供魔 | 检查受益颜色、施法费用、可回收法力和队列阻塞；大量造同色石加额外回合属于组合风险 |
| 敌方变形 | 视作可能使一个作战单位整体失能的效果；保留原生概率、目标和免疫规则 |
| 召唤／复制 | 检查空位、派生单位强度、满场失效、重复补员及派生单位再召唤；召唤强度纳入整队 |
| 群体控制／抽蓝 | 作用人数、概率、持续时间、是否反复封锁行动一起检查；冰冻和缠绕的实战作用分别处理 |
| 生命／护甲伤害缩放 | 与加生命、加护甲、治疗、属性窃取组合时检查成长速度，不能只按魔力倍率定价 |
| 骷髅生成／特殊宝石 | 检查攻击力、骷髅减伤、特殊宝石结算及四连收益；强度可能来自棋盘而非直接伤害段 |

普通生成禁止同时随机拼出“吞噬／处决 + 稳定自供魔 + 续回合”或“全体控制 + 低费循环”。特殊池只能采用经过整套行为验证的具体组合。限制应用于最终主动、独立特质和整个编队；同一条高影响效果若由特质提供，照样计入。

暂不引入一个声称已平衡的通用分数。现有 combatPower 只能做面板参考；机制准入、费用收益、循环检查分别保留诊断。

## 5. 伤害必须保留形态与完整数值关系

当前原生原型共含 1,245 个潜在敌方直接伤害段；按审计的互斥形态分类：单体 833、全体 160、溅射 82、散射 75、多目标 75、随机多轮 20。其中 1,197 段使用普通公式、19 段使用区间公式、29 段为即杀；区间和即杀的占位 scaling 未计入普通公式分位数。这里是效果段分布，单位可含多个伤害段；条件分支内有伤害也不保证每次施放造成伤害。

模板需保存这些内部标签，生成器按它们匹配：

| 维度 | 必须保留的信息 |
|---|---|
| 单体 | 指定／前排／后排／最弱／随机目标；目标变化和跨段追踪 |
| 群攻 | 每名目标各受同一伤害，还是只攻击限定人数；目标过滤规则 |
| 溅射 | 主目标完整伤害、相邻目标比例、中心数／多波选取、编队相邻关系 |
| 散射 | 是总伤害分摊，还是每次独立伤害；随机分配、存活目标与取整规则 |
| 多段／多目标 | 命中次数、是否可重复命中、随机避让规则及击杀后下一段目标 |
| 伤害性质 | 普通、真实、吸取、法力燃烧、处决等，与作用范围分别标记 |
| 数值组成 | 基础值、魔力系数、二次加成来源及比率、区间、条件倍数、加成上限 |

以现有模板为数值单位，继承其稀有度、费用和公式，以及技能内部固定的宝石颜色。generation v2 的实例充能配色由请求独立绑定；generation v1 和旧 native 的源配色及历史选择规则保留。当前汇总中，480 个伤害段含二次加成；其中自身护甲、自身生命和自身攻击分别有 26、25、16 个来源记录，此外有棋盘、队伍属性、已受伤生命、目标属性等来源。这些来源记录可能在同一个伤害段内同时出现。

费用较低的技能，基础值和魔力系数大多集中在“魔力＋若干”；高费用段出现更多倍率与组合。例：费用 25+ 的普通公式伤害段魔力系数 P25/P50/P75/P90 为 0.8/1/1.7/1.8。它不表示高费单体就应统一套 1.8 倍魔力：形态、基础值、副效果和条件还在同一个模板里。

本项目已有群攻调整：对应费用 28/30/32/34 的指定模板可使用 1.6/1.7/1.8/2 的魔力倍率，并保留原倍率例外及固定倍率例外。世界毁灭者保留原倍率，永生神路西法固定 1.5 倍；从最终原型继承，不按费用重新推算一次。

若以后需要生成新公式，必须先在相同稀有度、费用、伤害形态、受益人数和副机制预算内建立参考带；本阶段采用现有完整公式。伤害评估至少记录中性棋盘下的单体／整队伤害、条件收益、爆发上限和单位费用收益，不把最大条件伤害写成稳定伤害。

程序已有的等级成长及四维随机浮动沿用既有流水线。生命倍率与难度独立；报告要区分成长面板、四维浮动后的面板和战斗最终面板。生命／护甲型伤害按原生读取时点计算，并说明战斗生命倍率是否进入其基准。若生命倍率也放大其输出，需要纳入测试和预算，避免把该旋钮当成只延长战斗的参数。当前普通／困难和动态难度继续暂缓。

## 6. 宝石操作、供魔都要生成具体配置

用户和 AI 不负责手搓所有技能参数。程序选出的模板必须已经有下面这些规格，并在战前技能说明中写明可读的结果。具备 gemExplode、gemCreate 或 mana 标签，尚不足以通过参数验收。

| 类别 | 内部配置与生成规则 |
|---|---|
| 造石 | 宝石种类、基础色／骷髅／特殊种类、数量公式或区间、数量加成及上限、动态选色来源；特殊宝石不冒充普通法力石 |
| 转色 | 起始色／种类 → 目标色／种类，全转还是限定数量，选色限制、动态目标颜色、阶梯规则。零可转宝石时的结果由原生规则决定 |
| 爆破 | 爆心选择类型、爆心数量公式、颜色／种类过滤、选格／行列／区域、是否有邻格爆破；明确区分爆心数和最终清除格数 |
| 摧毁 | 仅清目标还是整行／列／区域，数量和筛选；与爆破的扩散范围分别处理 |
| 移除 | 保留原生移除语义，单独验证收益；不计作稳定供魔证据 |
| 直接供魔 | 具体对象、数值／比例、是否包括自身、法力上限与队列效果；它给单位法力值，不是凭空发某种颜色宝石 |
| 间接供魔 | 创造／转换成什么颜色，谁使用该色；爆破／摧毁按棋盘上实际有色宝石结算法力，记录损耗和队列分配，不承诺固定回蓝 |
| 风暴／特殊石 | 掉落种类、持续时间、特殊结算及双方收益，按已有棋盘规则执行 |

例如食人魔模板的“随机爆破 1 颗宝石”是一个爆心及周围区域，不是清一颗，也不等于固定回一蓝。爆破整片区域、只摧毁棕色宝石、移除全部棕色宝石，在范围、供魔和连锁上分别计价。双头怪的“摧毁一列 → 每颗紫石创造四颗骷髅”保留先后依赖，造石数量依赖实际摧毁结果。

组合时优先让供魔与队伍真实用色有关，但不擅自把原生固定颜色改成施法者颜色。模板写固定棕色就保留棕色；模板写 CASTER、CHOSEN_TARGET 等占位符就按原生解析（新实例配色先统一顺序，避免同一颜色集合产生不同第一色），并验证施法选择器有对应输入。支援生成器要检查被支援者是否存活、是否使用该色、有没有长期被前排截流。此类协同影响选取排序和整队验收，不把固定颜色全改成万能供魔。

## 7. 召唤与变形的对象属于模板本身

原生共有 172 个 summon 段（107 个固定引用、65 个随机池）、5 个复制召唤段、27 个变形段。它们分布在更少的单位中，不能把效果段数当单位出现率。

召唤模板必须有：固定单位或有效候选池、数量／区间、成功概率和前提、派生等级与属性来源、入场位置、初始生命／法力／状态、满四人时的结果。召唤出的单位也要验证完整主动、特质、立绘和派生闭包；大池由程序按族群／地区规则自动建册，非逐名手写配方。池中含高档单位时，需要计入该模板实际可能带来的战力，不通过召唤绕过档位门槛。

变形分别标记：自身变形、友方变形、敌方变形；固定目标形态、随机池或复制现场单位；替换哪些属性、能力和特质；生命、法力和状态如何继承；是否可重复触发。沿用引擎已有变形语义，映射到明确的派生模板。复制召唤、复制变形和狼化也要分别处理。

编译阶段解析并验证所有可能派生引用；随机池、复制现场单位及地区池的动态边界也必须接受检查。战前展示固定名称或池的可读范围，实际施放后显示真正召唤／变成的对象。只有一个 summon 或 transform 词，没有对象与继承规则的模板，验收失败。

## 8. AI 只填遭遇基础信息，程序生成完整战法

运行时 AI 选择是否交战、敌人数及每名敌人的 `rank`、`level`、`form`、`role`、`manaColors`，不编写 effects、技能／特质 ID、费用、公式、数量、目标、分支、机制权重、生成池或种子。运行时由程序补入 `assembly: "classified"`；省略 effects 对应 `[]`，不默补 damage。种子由程序保存，预览说明种子用于复现、换种子可换战法。

最小运行时示例：

```text
<match3>
{"enemyDesigns":[{"manaColors":["Red"],"rank":"杂兵","form":"人形","role":"Striker","level":20}]}
</match3>
```

高级手动入口和旧协议继续兼容显式 effects：`required` 逐项检查实际满足，`preferred` 只影响偏好。字符串简写等已支持的旧格式按解析器规范化。空数组表示额外效果约束为空，不表示技能没有效果；手动约束也不跨源职责池，不重写模板参数，不绕过准入。缺少合格模板时返回具体诊断。

旧 `native` 输入及存档沿用其版本语义与完整配置；旧 effects、偏好、费用、公式、特质顺序和结果指纹均纳入恢复兼容核验。新运行时入口固定 classified 与旧存档恢复是两条路径，不静默互相迁移。

伤害形态、宝石颜色和数量、召唤物等细节由完整主动模板提供。后续若有剧情限定需求，先设计版本化协议与验证，再单独调整 AI 输入；本轮不新增形态 effects 或主副意图字段。

## 9. 结构覆盖、机制行为与平衡分别验收

验收按共享机制和交互组合组织，不要求逐名手写配方。记录待测提交、策略版本、目录快照、完整命令、输入、种子、分母、实际输出和失败原因。核心与策略模块都完成后再独立执行；本文件中的清单和命令是准备项，没有执行记录的项目标为“待验证”。

| 验收层 | 要验证什么 | 证据边界 |
|---|---|---|
| 结构映射／编译 | 完整主动与有效特质、规则识别、真实立绘、派生闭包、蓝图保存恢复 | 显式 assembly 成功不证明 role 分池、随机权重、普通池准入或战斗收益 |
| 新生成规则／确定性 | 请求与源职责一致、unique spell 去重、池内分组加权、强机制限制、旧 effects、旧存档和上下文复现 | 采样覆盖不证明真实战斗行为；固定种子只证明相应输入的复现 |
| 机制行为 | 费用、伤害／宝石数量、实际目标、条件、随机分支、触发时序及跨来源叠加 | 有能力标签、描述文字或结构签名不足以证明执行 |
| 分类平衡／整队 | 施法节奏、费用收益、控制持续、连续行动、支援对象、派生收益和队伍胜率分布 | 行为正确与强度合适分别给结论；参考战力不是平衡签收 |
| 真实酒馆联调 | 入口、预览职责、战斗实际行为、战报、往昔再现和持久化上下文 | 浏览器预览通过不代替完整宿主联调 |

核心完成后的独立审阅清单：

- [ ] classified 请求职责与实际主动源职责一致；附带伤害、魔力系数或副特质不串池。
- [ ] 删除源主任务依赖的特质时，生成器保留任务证据或明确诊断；区分自疗／队友治疗、防护自身／防护队友、主动效果／特质效果及互斥分支。
- [ ] 按 unique spell 统计分组与组内候选；重复源条目、不同外观和特质组合数量不放大权重。保留实际公式、对象或费用有差异的合法模板变体。
- [ ] 普通池按最终主动＋特质限制低稀有度强机制；吞噬／处决、自供魔、额外回合与低费群控检查覆盖单体及跨成员组合。特殊池不绕过组合限制。
- [ ] 旧 native／classified 存档和高级 required／preferred effects 均按版本复原；不因新增元数据改变旧结果或吞掉旧偏好。
- [ ] 团队 context 参与筛选或加权时被规范化并持久化；保存、恢复、编队换位及重开使用一致的上下文，缺省与显式上下文的兼容边界有证据。
- [ ] 同种子及上下文生成同一完整结果；修改种子在有多个合法候选时可更换战法；不承诺每两个种子结果必异。
- [ ] 预览只显示请求的主职责，仍展示实际 effects、主动和特质描述；默认无手动效果约束，旧约束恢复后可查看和清空。

行为用例分别覆盖：单体／全体／溅射／散射、真实伤害与多目标、区间公式与多波随机；四维及棋盘数量缩放；造石／转色／摧毁／移除／爆破；空蓝／满蓝与施法队列；固定／随机召唤、复制与变形；空位／满位、派生等级及状态继承；条件依赖、跨段目标、死亡触发和互斥分支。

平衡模拟固定参考队伍、等级、数值浮动种子及棋盘种子，分别记录首次施法回合、可施法频率、每费用收益、无效施法、控制持续、连续行动长度、召唤收益及胜率分布。阈值由分布和实测校准，不从目录出现率推导固定输出人数配额。

## 剧情显示身份

运行时 AI 为每名敌人提供 `name` 和 `race`，与正文的人物姓名／称呼和世界观种族一致；另外五项仍为 rank、level、form、role、manaColors。组装器保留这些文字用于入口、准备、战场、图鉴及往昔再现。剧情种族不覆盖实际技能使用的抽象族群关系，不参与选图、随机权重、面板和能力学习身份；同名敌人也不按原项目同名兵种取技能资料。
