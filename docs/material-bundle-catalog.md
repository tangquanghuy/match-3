# 材料商店：按配方组合选购

日期：2026-10-01。当前仅本地修改；提交部署暂停。

## 玩家可见变化

- 宝石区移除“选择部队”的收藏下拉，改为 **组合类型 → 属性组合 → 特质阶段**。
- 当前全目录归并为 **13 类配方、204 个属性版本**。相同逐阶段材料配方合并为同一商品，收藏上千部队也只显示13个分类，每页最多5个属性条目。
- 支持六属性筛选、翻页；属性条目使用已有压缩秘法立绘。
- 包括普通/精良/稀有/传说/史诗的单色、双色配方，以及神话双秘法、圣辉等特殊配方。名称沿用项目既有品质词表。
- 明细按初级、高级、符文、秘法、圣辉顺序列出准确颜色、数量及当前库存，不用随机颜色代替配方。
- 默认购买三特质整套，也可选择后两阶或第三阶；特质页直达时自动定位对应配方及尚未解锁阶段，保留返回入口。
- PC目录翻页和购买按钮保持可见，列表与材料明细各自滚动；窄屏纵向浏览，点击属性条目后滚动到明细。
- 金币单价、跨颜色共享的前84颗秘法优惠、宝石材料单价均未调整。已有库存不抵扣组合数量，不新增培养目标。

## 配方与交易

单源：`src/meta/data/materialBundles.ts`。

1. 从全目录的 `traitUnlockCost` 派生三阶段配方，包含导入及社区回退配方。
2. 按逐阶段材料字典规范序列化去重；类型按逐阶段品阶数量结构归类，并非按玩家收藏或部队晋升品质分类。
3. 商品ID由配方内容生成，有碰撞检测，不依赖部队ID或数组顺序。
4. 正常订单为 `{kind:'gems', bundleId, mask}`。阶段掩码7/6/4分别为全套/后两阶/第三阶。
5. 服务端只从自身目录重算配方和价格，校验阶段、商品与报价；客户端附带的价格、材料字典不作为交易依据。
6. 商品不要求拥有某名部队；购买只是材料入库，不解锁特质。解锁/晋升/收藏变化不改变固定商品。
7. 保留旧 `troopId` 订单的配方转译及 `#materials/gems/<troopId>` 定位入口；新页面提交组合ID，不再以部队作为商品。
8. 标准商品链接 `#materials/gems/<bundleId>/<mask>` 支持刷新；可带末段部队ID作为返回入口，不参与配方或定价。
