# GoW 部队与武器技能：逐项一致性验收规范

## 验收目标与边界

逐个确认项目中每名原版部队、每把武器的**完整主动技能**与有据可查的 GoW 原版规则一致，包括显示描述和实际出战结算。禁止以“已登记”“编译 full”“能施放”“一个种子没报错”替代语义签收。

- 实体清单来自 `TROOPS` 与武器目录，按 `troop:实体ID` / `weapon:实体ID` 独立登记。共享技能可以共用机制测试，但每个持有者的费用、颜色和绑定独立确认。
- 自设部队单列，不计入原版一致性分母；仍保留记录，防止被遗漏或误配原版来源。
- 未实装模式和晋升依赖项按**具体子句**排除，写明来源、理由及实际缺少的系统。涉及同一技能的普通伤害、状态、宝石操作照常验收。
- 淬炼、活动 Boss 条件、灵魂/金币收益不按关键词自动排除。先确认是否落入用户排除范围，未确认的保留待核查。
- 本轮主动技能审计不代替部队特质或武器词缀审计，也不声明这些被动效果已对齐。

## 参考基线

1. 保存来源版本、原文、获取时间（有记录时）和 SHA-256。已存原始资料为 gowhead.com 抽取快照，明确不是官方实时接口。
2. 优先补充官方更新公告、官方人员规则解释及可复核的原版实测。原始步骤与英文描述互相交叉验证；二者冲突时登记为来源冲突，先不签收。
3. “当前 GoW”与“仓库快照版本”分开记录。没有完成版本更新核对前，只能报告快照一致性。
4. 原文没有给出的隐藏概率、目标抽样方式、取整、结算时机等，不以项目现有实现倒推原版预期。保留待考证状态。
5. 测试预期来自独立原版依据，不从同一编译器或最终原型生成期望值再比较自己。

## 每个技能的12项核对

| 维度 | 检查内容与关键边界 |
|---|---|
| 身份、费用、颜色 | 原版实体/技能ID、基础费用、颜色、最终目录及出战绑定；武器数字ID和 `gw_*` 键 |
| 目标、数量、范围 | 选择/随机/首末位、敌我、相邻、溅射/散射、多段是否重复选中 |
| 基础数值与取整 | 常数、魔法系数、取整位置、零魔法、奇数魔法、真实/普通伤害 |
| 增强来源、倍率、上限 | 施法者/目标属性、宝石、队伍、资源、状态计数；先计数还是先消耗 |
| 条件、概率、分支 | 条件真/假，独立/嵌套概率，边界随机值，玩家选择与随机选择 |
| 状态与免疫 | 状态种类、目标、层数、时长、净化、解除、免疫、屏障、诅咒等共享机制 |
| 宝石与后续结算 | 宝石类型、数量、转换、创造、摧毁/消除/爆破、收益、连消与回合 |
| 召唤与变身 | 对象、池、等级/属性、队伍容量、位置、法力、继承、免疫 |
| 顺序、死亡与重选 | 前后段顺序、致死、移位、再选目标、最后一个敌人、空目标 |
| 法力、资源与额外回合 | 扣费、返还、收益、封顶、击杀条件、来源、额外回合和冻结交互 |
| 玩家描述 | 英文依据、中文文案、公式、目标、概率、条件全部一致；来源文本与显示层区别 |
| 真实战斗入口 | 部队及武器各自最终注册路径，玩家/AI选择，实际施法事件和状态 |

## 单项签收要求

每个实体必须同时具备：

- 原文完整子句清单；每个子句标为“已核对”“有差异”“需证据”或“明确排除”，没有空白。
- 12个维度逐一核对；不适用项写出理由，而非缺少测试即自动不适用。
- 基础用例与所有不同条件分支；涉及相关机制时增加护甲/生命、免疫、空位、死亡、数量和阈值边界。
- 来源依据明确的独立期望；实际施法路径的结果与期望对应。
- 中文显示与实际实现一致，修复后重跑相关技能及共享机制回归。
- 审核人/审核时间、来源哈希、实现哈希、测试证据。依赖的引擎规则变动后标记需要重验。

发现一个差异即可判定“当前不一致”；**这不代表该技能其他效果已经检查完**。一个基础用例通过也不代表整个技能通过。

## 执行顺序

1. **全量建账**：逐实体关联英文、原始步骤、最终注册原型和显示文案；统计资料缺口；保留未实装原版实体旁表。
2. **共享基础规则核对**：伤害、散射/溅射、状态持续/解除、免疫、宝石收益、额外回合、死亡时序。共享规则未确认时，相关技能保留依赖项。
3. **优先处理高风险实体**：已确认差异、部分编译武器、手写覆盖、来源冲突、选择分支、随机多段、状态/召唤/变身、增强及击杀奖励。
4. **余量逐个确认**：按类别和实体ID分批，保留逐实体逐条证据，禁止将未检查余量默认通过。
5. **修复与回归**：每处差异先建立独立失败用例，再修改最小实现范围；共享机制改变后重验全部受影响项。用户未要求的自设角色平衡不随原版校正一起调整。
6. **最终门禁**：所有在范围内子句和维度已签收，资料冲突已解决，真实管线与回归通过，才输出整体完成结论。

## 当前工具的能力边界

`node scripts/audit-gow-skills.mjs` 生成清单、风险提示、首批人工核实差异及少量独立真实施法探针。它**尚不是全量语义判定器**，不会自动生成“整项通过”。

- `ledger.json`：逐实体英文子句、原始步骤、当前显示/原型、12项维度、差异、证据和指纹。
- `review.html`：离线搜索查看全部实体，已确认差异优先排列。
- `checklist.csv`：表格筛选。
- `probes.json`：少量真实战斗入口对比；局部匹配与不匹配都记录。
- `--check`：严格完成状态检查，未完成时返回非零；报告正常生成和验收完成是两个状态。

现有进度由 `docs/gow-skill-acceptance-progress.md` 和上述产物记录。后续逐项审核需要扩展持久化签收记录、完整独立用例及证据核验；不是反复运行同一个建账脚本就能完成。
