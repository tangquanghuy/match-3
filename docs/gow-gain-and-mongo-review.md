日期：2026-09-26。范围：10 个技能的明确条款修复；**不是 10 个整项技能签收，也不是全量最终验收**。

## 独立资料与测试口径

- 原版英文实体快照：`data/raw/troops.gow.en.json` 与 `artifacts/gowhead-weapons/weapons.json`。
- 原始机器步骤：`data/raw/spells.gow.en.json`，使用 `indexNativeSpells` 从 `RawData` / `data` 按负载技能 ID 索引；避免部队 ID 与技能 ID 碰撞。
- 资料是仓库保存的第三方抽取快照，不宣称官方最新版本。
- 部队验证最终注册原型与 TurnEngine 施法；武器验证真实装备 `gw_*` 注册键及数字别名。
- 全量测试结果以 `artifacts/gow-skill-audit/verification-receipt.json` 中**匹配当前账本指纹**的凭证为准；本页不硬编码历史通过数量。

### 蒙戈：原始六分支

| 分支 | 原始步骤 | 当前接入 |
|---|---|---|
| A | Consume / RandomEnemy | 随机敌人吞噬，复用现有吞噬管线 |
| B | TransformType / Self / fey | 自身转化为一名已实装原版妖精，复用现有转化模板 |
| C | RandomStatusEffect / AllEnemies | 全体敌人随机负面状态 |
| D | ExplodeGems / Amount:10 | 爆破 10 颗随机宝石，覆盖全部宝石类型 |
| E | IncreaseAllStats / RandomAlly / M+10 | 同一名随机盟友四属性各增加 M+10；第一段选目标，其余绑定 lastTarget；生命同时增长当前值和上限，魔法最后增长避免自身重新缩放 |
| F | SplashHeavyDamage / RandomEnemy / M+2 | 随机目标 M+2 重度溅射，相邻槽位伤害比例 75% |

旧版本的 M+8 普通伤害、M+8 单生命、全队固定 4 护甲、全队固定 3 法力及 3 宝石爆破已移除。旧自定义分支的断言也替换为独立快照对应的测试，未保留错误行为作为验收标准。

妖精池包含项目实装原版目录的 145 名妖精。英文快照另有 7910/7911 两名妖精不在当前实装目录，已显式保留范围差异；未把它们自动补入目录，亦未把该池视为官方实时完整转化池。

### 窃贼大王：黄金增强解释

英文和中文都明确 `[5:1]`。原 `CountMyGold Amount:20` 被错误解释为“每20黄金+3”；同一快照中的 8142、7958 都使用 `CountMyGold Amount:20` 且描述 `[5:1]`，支持这里的20是计数系数，而不是黄金分母。

修复的独立期望依据描述 `[5:1]`，测试黄金 0/4/5/9/10/19/20/21/24/25/99/100，魔法 0/1/11/20；同时验证伤害所选敌人、增益仅自身、黄金未被消耗、受伤时 current/max Life 同额增加，以及先伤害后增益。未对所有百分比计数或更大黄金值的取整方式作批量认证。

## 仍待核验的依赖

- 吞噬共享实现仍使用固定成长并经过伤害管线；原版成长、屏障／减伤／免疫交互尚未获整套独立认证。本次 A 分支仅证明正确调用 Consume 分支，不给共享吞噬规则签收。
- 随机负面状态的完整池、持续时间、免疫与诅咒交互未被 C 分支基本用例替代。
- 妖精转化的官方排除池、等级、属性继承、状态继承、免疫以及不朽单位资格仍待核验。
- 大天使只验证同一施法者重复使用限制；双方、重复单位、转化／复活后的单次规则仍未签收。
- 六件武器的 Bless 基本目标筛选已验证，但 Bless 状态全规则一致性另列。
- 黄金仍采用共享经济池，施法者／敌方资源的独立池模型没有在本轮重构。

## 新登记的两项差异

- **9783 黄金窃贼**：伤害公式已修，但黄金窃取仍有差异。native `TakeEnemyGold 5` 后 `GiveGold 5`；当前只增黄金，未扣敌方资源池。
- **8073 黄金枪**：native 同时计数我方、敌方黄金；当前增强只有共享 `battleGold`，缺少敌方独立黄金来源。

它们与已有 8859 黄金窃取差异及 9185／8869 来源冲突一起留在账本，未归为已修复。本报告列出的局部范围测试通过也不消除这些未决项。
