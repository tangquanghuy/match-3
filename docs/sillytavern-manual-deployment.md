## 正则内容与设置

查找表达式：

```regex
/<match3>\s*[\s\S]*?\s*<\/match3>/g
```

完整替换内容随 JSON 一起导入，包含 fenced HTML、`<body>` 和消息入口模块加载代码。它读取当前消息的原始 JSON，再进入现有准备／战场页面。启动时先显示加载提示，动态加载模块及获取消息编号的异常会显示在入口中。

JSON 文件请使用正则扩展的导入功能。手工编辑替换框时，使用 `sillytavern-runtime-regex-replacement.txt`（包内名 `runtime-regex-replacement.txt`）的全文；保留首尾代码围栏。JSON 中的 `\"` 是文件编码的转义形式，直接粘贴到 JavaScript 地址两侧会导致语法错误和空白入口。本版模块地址使用单引号，并提供独立 TXT，省去手工解码。

| 设置 | 值 |
| --- | --- |
| 脚本名 | 三消·正文战斗入口 v1 |
| 作用位置 | AI 输出（placement: [2]） |
| 仅格式显示／Markdown only | 开启 |
| 仅提示词／Prompt only | 关闭 |
| 编辑时运行 | 开启 |
| 禁用 | 关闭 |
| 最小／最大深度 | 留空 |

导入后确认同名规则只启用一份，移除旧方括号匹配版本。启用酒馆助手的消息内 HTML 渲染。原消息中的 `<match3>` JSON 保留，显示层替换成入口卡。

底栏与开局沿用原角色卡已有显示规则，其匹配标签没有变化。正式入口只新增这一份三消正文正则。

## EJS 与地址

提示词模板扩展在发送前读取 `stat_data.系统配置.三消战斗模式`：开启且未屏蔽战斗上下文时注入三消规则；关闭时注入原生规则；屏蔽时两份都为空。世界书中保留 EJS 模板，发给模型的内容应是选定的规则正文。

当前底栏、可选面板包装和仓库正则指向 `https://match3-tavern-playtest.linjiang-workshop.workers.dev/`。更换站点时，更新底栏的 `MATCH3_PANEL_MODULE_URL`、可选包装的 `MODULE_URL`，并从新站的 `sillytavern-install.html` 下载正文正则。JSON 内模块地址随安装页所在目录生成。

自建站点使用 `npm run build:tavern` 生成整个 `dist-tavern/`。当前 Cloudflare 发布配置为 `deploy/sillytavern.wrangler.jsonc`，命令为 `npm run deploy:tavern`。站点需要跨来源模块访问；构建 `_headers` 已包含对应配置，自建其他服务器时按其格式设置。

## 人工验收顺序

1. 在测试聊天打开底栏设置，开启三消并打开面板，确认当前聊天绑定与编队可用。
2. 在提示词模板的实际发送预览中检查两份战斗规则互斥，三消规则示例使用新标签。
3. 让 AI 产生新遭遇，确认原消息是 `<match3>` JSON，显示层出现战斗入口卡。
4. 从入口进入准备与战场，验证嵌入／全屏及刷新恢复。
5. 结束战斗，核对本场结算、变量战果和下一轮模型实际收到的战报；再验证往昔再现入口与能力学会后的限制。

当前新协议解析以尖括号为准。旧聊天中的方括号战斗入口不自动改写；未完成旧遭遇先处理完再升级，或在独立测试聊天生成新入口。既有三消存档保留。本次发布和自动回归的具体结果见 `tasks/active/STATUS.md`。
