# 敌人行为验收证据

本文件规定 ST-04 逐敌人行为覆盖的证据入口。可编译、原生已注册、说明结构完整与逐敌人完整行为通过分别计数。逐敌人达标后，ST-04 仍须关闭共享设计词表、语义编译、职责和整场强度预算等产品义务。

## 验收范围与原生证据复用

ST-04 的交付目标是完整组装原生能力并正确接入酒馆战斗。既有原生游戏的资源池、HUD、技能执行器及机制测试直接复用；完整组装验收不扩大为重新逆向审计全部原生技能。独立审查的责任对照与实际反例见 [ST-04 审查记录](sillytavern-st04-review.md)。

13 项义务保持，每名来源分别关联证据，但共享机制不要求为每名来源重写同一份测试：

- 先登记明确覆盖该能力的可信原生测试及原始条款，复用其机制、数值、目标、消耗和 RNG 证据。原生证据缺失或与原文冲突的部分单独列缺口。
- 每名来源仍执行自身真实 ST 配置，验证能力与普通特质完整保留、身份与上下文绑定、输入元数据、缩放、依赖预检、保存恢复及原生执行一致性。
- 机制家族复用已有区别性场景，补充适配边界与真实反例；召唤、复制、变形、条件、选格、延后效果及异构上下文不能只由一次首发对照代替。
- UI、AI、引擎的真实行为保持一致。只检查内部方法返回值的浏览器测试不代替实际卡面、按钮或交互检查。

同一稳定树的测试文件及参数组合只执行一次，各来源引用精确断言与原始报告，不按来源重复计测试数量。现有登记、指纹及机器验证规则继续执行；跨文件原生证据与家族证据通过下述文件及断言引用关联，工具切片仍须独立审查，目录首发通过不自动升级为完整来源通过。各原始稀有度及通用五档分别至少 90% 的门槛保持。

当前全树指纹仍会让无关改动使旧收据失效。后续分层依赖与影响范围缩窄需先做影子验证，覆盖能力使用者、特质持有者、动态候选池及派生闭包；核心变化或依赖不明时保守扩大。该优化尚未实现，不据此豁免本轮续签。

## 登记与执行

登记文件为 [st-enemy-acceptance.json](../data/audit/st-enemy-acceptance.json)。每名敌人独立列出测试文件、运行收据、审查收据及各项义务对应的实际测试全名；不登记人工通过布尔值。义务至少包含立绘、完整主动、适用特质、目标、法力成本、关联颜色、等级与难度缩放、上下文绑定、说明、职责、刷新、确定性和无效行动原子性。

源语义的期望来自独立核对的原始条款与数值。测试须从正式 ST 蓝图、准备校验、注册和会话入口执行，既覆盖单项机制，也覆盖实际特质与主动的组合；未知效果或依赖保留为缺口。通用技能释放无异常或原生／适配结果相等，均不足以证明完整语义。

```powershell
node scripts/st-enemy-acceptance.mjs --enemy 6004 --author codex-main
node scripts/st-enemy-acceptance.mjs --enemies 6001,6004 --author codex-main
node scripts/st-enemy-acceptance.mjs --all-registered --author codex-main
node --test tests/scripts/st-enemy-evidence.test.mjs tests/scripts/st-evidence-paths.test.mjs tests/scripts/st-enemy-acceptance.test.mjs
node scripts/st-enemy-inventory.mjs
node scripts/st-enemy-inventory.mjs --check
```

登记的 `testFile` 保持为主文件；可选 `testFiles` 声明包含主文件的完整测试文件集合，各路径唯一。义务可以沿用单文件断言全名，跨文件建议使用 `{ "testFile": "tests/unit/native.test.ts", "fullName": "完整测试名" }`。同名断言出现在多个文件时必须明确文件，其他文件的同名成功不能替代本文件证据。声明的每个文件均须实际产出通过断言，缺文件或跳过继续失败。

原生测试读取的树外源资料（例如 `data/raw/` 原文和 `artifacts/gow-source-fixtures/` 历史快照）须在 `evidenceFiles` 列出实际文件；这些文件字节计入执行指纹，独立审查核对测试的真实读取依赖。新映射台账 `data/audit/st-native-evidence-map.json` 仅登记已检查的具体引用及剩余缺口，映射本身不增加通过数。引用它的测试同样须绑定该文件。

批次执行对所有来源的测试文件取并集，只启动一次 Vitest，保留原始共享报告及哈希，按实际文件与断言分配逐源收据。完全相同的保守目录快照在一次同步批量指纹调用内复用，输出与逐源读取一致；执行后重新读取完整快照核对，没有跨调用缓存，也没有缩窄依赖范围。

运行脚本实际执行登记的整个 Vitest 文件，保存每项断言状态、测试数量、命令和内容指纹。失败、跳过、零测试或运行中依赖变化均不计为通过。执行者不能代替独立审查者填写签收；独立子 agent 必须核对当前运行产物、义务映射和源语义，再签收明确范围。

## 内容指纹与签收

收据绑定当前敌人的完整索引内容、适配和执行实现、源数据、测试文件以及实际立绘资源。SHA-256 指纹分别记录被测对象、执行依赖、测试及立绘；当前采用保守目录快照：执行摘要覆盖 `src/` 与 `scripts/` 全树，测试摘要覆盖 `tests/` 全树的测试、辅助模块与夹具；两者均绑定根 Vite／Vitest、tsconfig、package 及锁文件，新增、删除、改名与内容变化均使旧证据过期。保留必需文件存在性检查及所选测试文件的独立绑定；另将登记的 `evidenceFiles` 实际字节加入执行摘要。未解析完整 import graph，未声明的范围外输入、实际 node_modules 内容及环境变量未纳入，尚未按机制家族缩小重跑范围。编队、经济账本或单条伤害的审查只证明其声明范围，不能直接签收整名敌人。

审查收据另行保存 reviewer、`enemy-behavior` 范围、全部义务 ID、当前对象／测试摘要，以及实际运行收据摘要。运行和审查双方的 `contractDigest` 均须匹配完整登记记录，绑定全部义务到断言映射、来源引用和文件路径；改动映射也使旧收据失效。实现者与签收者须不同。运行退出码须为数字 `0`，缺失、字符串或非零值均判失败。登记、测试、运行／审查收据和临时报告均检查真实路径；已有目录链接越出项目时中止，新文件也检查最近已有父目录，并在写入前复查。任意指纹不符后，旧证据成为 `stale`，须重新执行并确认审查仍适用。

## 覆盖统计

生成器从完整 1821 条运行目录出发，以稳定敌人 ID 关联证据；重复登记和孤儿记录报错。没有记录、缺收据、缺义务、失败、跳过、过期或尚未独立签收都继续留在缺口。仅 `passed` 记录进入完整行为通过分子，每个原始稀有度和通用五档分别以 `ceil(适用数 × 0.9)` 判定。

首个样板为 6004 火枪手。它用于打通可审查的行为证据路径，不降低任何稀有度门槛，也不代替其余敌人的实际测试。普通经济与复杂机制、召唤／变形候选和原有覆盖分母保持完整，普通战中资源复用原生执行；后续按家族复用场景，但每名敌人仍须执行自己的配置并有明确签收范围。
