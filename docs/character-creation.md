# 初次登录角色档案

## 产品流程

- 新账号登录后先进入 `#character`，确认角色后进入原有新手引导；待建角账号访问其他游戏路由仍进入建角页。
- 角色 ID 取自本次 Discord 登录的账号名称，界面只读。Worker 使用已鉴权的玩家 ID 查询账号表，忽略客户端传入的名称。
- 性别为男 / 女 / 未知；可选择任意默认立绘、本地上传或 HTTPS 图片直链。
- 设置中重置全新档后，成功响应同时清除登录 Cookie，页面返回封面登录入口（远端 `/`，本地 `/cover.html`）。再次登录后重新建角。
- 旧存档缺少 `character` 字段时迁移为原有主角，保留进度；显式 `character: null` 表示等待创建。

## 资源

默认图为用户提供的三张原图，依次对应男、女、未知；使用 WebP 压缩，未重绘或裁切源文件。三个文件均为 800 × 1200：

| 文件（`game-assets/public/static/hero/`） | 大小 |
| --- | ---: |
| `character-male.webp` | 128,802 字节 |
| `character-female.webp` | 162,852 字节 |
| `character-unknown.webp` | 111,354 字节 |

封面预加载优先队列包含三张默认图，生产构建预加载清单也包含这些资源。原始 PNG 只保留在本地忽略目录 `artifacts/character-user-originals/`。

## 上传及存储约束

- 接受 JPEG / PNG / WebP，本地文件上限 10 MiB、解码尺寸上限 4,000 万像素。
- 客户端先压缩为 WebP，再递减分辨率与质量，使 data URL 不超过 48,000 字符，兼容现有 64 KiB 命令请求上限。
- 服务端校验性别、图片类型与长度；默认立绘保存为 `default:male|female|unknown`。
- 网络图片保存 HTTPS 直链，不由服务器下载或托管；预览须加载成功后才应用，并使用 `no-referrer`。原站失效时，游戏内展示回落到默认图。
- 创建为一次性持久化命令，服务端拒绝重复创建，未建角账号受服务端游戏命令门禁限制。

## 验证入口

- `tests/unit/characterCreation.test.ts`：身份来源、存档迁移、门禁、图片校验、重复创建、重置重建。
- `tests/unit/coverPreload.test.ts`：含建角立绘的优先预加载。
- `tests/e2e/characterCreation.spec.ts`：三种性别、持久化、默认/上传/直链立绘、异步竞态、重置、旧档，以及桌面/手机/横屏布局。
- `tests/e2e/onboarding.spec.ts`：建角后完整新手指引。
- 本地独立 Worker 验证脚本：`artifacts/character-remote-check.mjs`，覆盖 D1 + Durable Object 的实际鉴权身份、上传持久化、重置清 Cookie、重新登录、浏览器建角和设置重置。

本轮本地测试使用 Vite 5174 与隔离 Worker 8788，避免占用其他项目的 5173 服务；使用的 Playwright 覆盖配置为 `artifacts/character.playwright.config.ts`。本地测试与截图产物不入库。
