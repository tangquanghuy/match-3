## 原始目标

用户在 [U003](user-dialogue.md#u003) 提出：把本项目作为文字冒险跑团的战斗部分接入 SillyTavern；运行时 AI 在正文里生成一小段描述敌人的战斗块，酒馆正则将其替换为远端网页入口，玩家在嵌入页面完成战斗，再把真实战报反馈给酒馆，由 AI 演绎后续文字。

用户倾向游客模式，把玩家进度保存在浏览器本地数据库。静态网页仍需部署和访问；这个要求没有承诺远端页面离线可用。三消与原生 AIRP 应通过角色变量和数值衔接，技能体系保持各自职责。目标是支持不同世界观的通用战斗接入，并持续复用本项目已有能力、资源和页面，避免维护第二套战斗引擎。

[U004–U005](user-dialogue.md#u004) 进一步提出武器附加能力、固定同行者、击败敌人收集灵魂碎片并装配同色能力、以酒馆数值为基础衔接。AIRP 自身的技能树、资源技能与特质不直接充当三消技能。

## 最终应达到的玩家体验

1. 玩家通过角色已有开局页启用三消，进入自己的酒馆聊天。系统为当前聊天使用独立三消档；打开另一聊天时切换对应档。达到三个绑定后，增加聊天由玩家选择删档。
2. 剧情真正进入交战，AI 给出世界观内的敌人身份并输出一块最小战斗配置。正则与酒馆助手渲染战斗入口；正常阅读、刷新、重新渲染消息只呈现入口。
3. 玩家显式点击后使用原三消战前加载与准备体验，查看真实立绘和原生详情，配置自己的队伍。程序选定技能、特质、画像和波动数值并冻结，重复打开沿用本场结果。
4. 玩家在原战场操作三消，能查看真实能力、费用、目标、条件与属性变化。原生三消的已有玩法保持可用。
5. 终局先生成并保存唯一收据，再使用原生结算页展示胜败和本场实际所得。碎片有玩家看得懂的来源名与数量；奖励卡、存档余额和收据逐项相符。失败、重复提交、重开结算分别按原收据处理。
6. 程序把本场真实战报和生命变化同步回酒馆；AI 收到战报后按人物关系续写。同步失败保留结果并允许重试，重试沿用同一战果。AI 无需核对内部编号，也不自行演算三消结果。
7. 玩家从底栏打开独立管理页，编队、装配、查看收藏。未学能力可以在往昔再现中挑战原整场敌方配置；我方用当前配置的独立满血快照，再现不扣酒馆 HP 或推进 AIRP。
8. 有效胜利累计魂片，学会能力后为兼容颜色的同伴装配；没有对应同伴也可先收藏。某能力学会后同能力来源全部停止刷取，遭遇全学会后保留查看记录并关闭挑战。
9. 首个完整养成版本还应完成武器登记、材料与淬炼闭环、导出导入恢复，以及多档隔离。临时 HP、逐行动恢复和数值标定按当前任务书补齐。
