# 双方黄金计数与窃取：限定范围复核（2026-09-26）

本记录针对项目所存 GoW 原版资料快照，不声称已核验 2026 年最新客户端。整项签收仍须逐实体完成。

## 原来的差异与修复

- `economy.gold` 原为双方共享池；现明确为 Left 的战斗黄金/奖励口，Right 独立持有 `enemyGold`。旧手写状态缺少 Right 字段时按零处理。
- `battleGold` 按施法者归属读取；新增 `enemyGold` 与 `bothGold` 来源。黄金获得、花费、阈值、赃物宝石及身亡黄金归对应阵营。灵魂/宝石/藏宝图不随本修复变更。
- 定量窃取扣除敌方可用余额并等额增加己方；全额窃取转移敌方全部余额。`goldStolen` 记录实际扣减额，不再用己方余额或额定上限冒充。
- 7505、8568、8859、9783 从普通 gainGold 改为敌方余额转移；8087、8141、8904、9189 通过共享窃取原语取得真实余额行为。
- 8073 黄金枪改为双方黄金之和的 `[2:1]` 加成，生成器同样修复。合计后向下取整是目前实现和测试的口径；百分比 counter 的原版精确取整时机仍待独立认证。
- 8087 原始顺序为敌方扣款→伤害→己方入账，新增 deferCredit 实现；9189 原始顺序为伤害→流血→黄金转移，已恢复。描述词序不等同原始执行步骤。

## 来源

- 英文部队：`data/raw/troops.gow.en.json`；英文武器：`artifacts/gowhead-weapons/weapons.json`。
- 原始步骤：`data/raw/spells.gow.en.json`，以 `indexNativeSpells` 识别 SpellData 字段，避免与 troop ID 混淆。
- 官方论坛工作人员 Saltypatra 的历史说明（topic 57352，2019 年 4.5/4.6 更新时期）：窃取动画可能在实际未取得黄金时播放，应以黄金计数为准。归档 `artifacts/gow-skill-audit/gold-primary-sources/57352.json`。该说明支持“播放窃取不等于取得黄金”，不认证本轮全部公式。
- 54984、59955、44000 是历史用户缺陷讨论，单列为辅助线索，不当作官方规则签收证据。
- 复核记录写明 8859 的 CountEnemyGold(1) 与 GiveGold 使用 counter、9783 固定 GiveGold(5) 在余额不足时的解释仍待独立证据；没有把“检测器不再报缺段”当成这些问题全部解决。

## 测试证据

`tests/unit/gowGoldOwnershipAudit.test.ts`：149 条，包括所有 8 项已实装原版 TakeEnemyGold 部队和黄金枪的真实 TurnEngine 入口；Left/Right 双向、零/不足/充足余额、随机目标、施法者被反射杀死移出后的黄金归属、献祭后来源/阈值/花费、取消/另一分支、守恒、跨段实际窃取额、黄金阈值和赃物宝石摧毁。这里只认证列明的实现范围，不认证原版全部隐藏规则。

`tests/unit/gowRegenerationAudit.test.ts`：黄金枪加入重建防回退，当前共 104 把武器进入原型对照。

1. 每队黄金上限、超限/封顶与转移的相互作用，未借本轮擅自引入通用 100 上限。
2. 两个百分比 counter 的累计/取整顺序，以及 8859 的异常 counter。
3. 9783 固定 GiveGold5 在低余额时是否采用实际可转移额；目前遵照英文“窃取”及共享窃取规则，仍保留待验。
4. 状态、免疫、流血层数、死亡后目标绑定、创造宝石后级联法力与额外回合等相关完整子句，须分别验收。
5. 全体来源冲突及未实装模式/晋升依赖只逐条排除；共享黄金模型修复不自动签收任何整项。
