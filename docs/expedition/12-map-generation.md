# 深渊远征 · 局内地图生成（生成器第 4 版）

本文定义局内地图怎么由种子生成。玩法规则以 `01` §3–§4、`02`、`03` §8 为准，这里只写生成和组装的做法。

原型实现：`.superdesign/design_iterations/expedition_mapgen.js`（纯函数，浏览器和 Node 都能跑），地形绘制：`expedition_terrain.js`，批量校验脚本：`.tmp/mapgen-check.cjs`。正式实现要移到服务端，算法和配置表照搬。

第 3 版把地图改成《黑色幸存者》那种区域图：一块俯视的高原切成若干有名字的区域，只有相邻、并且开了通道的区域之间能走。第 2 版的浮岛加桥已经废弃。

第 4 版在区域图上加了两样东西：

- 分层：三个环就是往下的三层，加上渊底的首领殿。每层有自己的名字、地名表、地面贴图和地标（§2.3）。每个区域下面的深渊按那个区域本地化（§2.4），原型只做了寒冬堡垒下面的霜渊。
- 冰潮：灯火（明亮度）机制取消。步数只在服务端记，玩家看不到；玩家看到的是每隔一段时间冰潮上涨，封住一批区域（§2.2）。

## 1. 原则

- 同一个种子、同一个生成器版本，永远生成同一张图。run 状态只存 `seed + 版本号 + 动作序列`，断线重进、服务端结算都按它重放。
- 结构和内容都随种子变：环上的节点数、连线、缺口、撤离点位置和窗口、事件位置、每个房间是什么、房间里有什么敌人和掉落、巡逻路线。
- 生成器拆成独立的步骤。每一步用自己的随机流（`种子 | 版本 | 尝试号 | 步骤名`），改动一步的规则不会让其他步骤的结果跟着漂移。
- 先生成、再校验。校验不通过就换下一个尝试号重来，尝试号也是确定的，所以结果仍然可复现。
- 客户端只渲染，不参与生成。房间内容在玩家看清之前不下发（防止解包看图）。

## 2. 管线

| 步 | 函数 | 输入 → 输出 | 要点 |
| --- | --- | --- | --- |
| 1 | 骨架 `buildSkeleton` | 出征类型 → 三环站点（角度、半径、外形） | 节点数在区间里抽；整体旋转随机；每个点角度抖动 ±20% 间距、半径抖动 ±6%；外形见 §2.1 |
| 2 | 站点布局 `layoutSites` | 站点 → 屏幕坐标、高原外轮廓 | 正俯视，y 压扁到 0.52；按包围盒等比缩放、居中到安全区；站点两两推开（普通 ≥ 150px，首领殿 ≥ 175px），每轮推完收回安全区；外轮廓 = 站点外扩 132px 再平滑，外面是深渊 |
| 3 | 区域切分 `buildRegions` | 站点 + 外轮廓 → 每个站点一块区域 | Voronoi 切分，裁到外轮廓里；记下每两块区域的共享边界长度 |
| 4 | 外环修补 `repairRim` | 区域 → 区域 | 外环相邻两块区域被里面的区域隔开时，把隔开它们的站点往首领殿挪最多 36px 再重切，最多 8 轮 |
| 5 | 连线 `linkGraph` | 区域 → 图 | 只在共享边界 ≥ 44px（`MIN_DOOR`）的两块区域之间开通道。外环必须成环；中环切 1–2 个缺口，内环切 1 个；环间通道在内侧环上均匀挑点，连到共享边界最长的外侧环区域；被缺口切出来的孤立段补一条向外的通道；首领殿只从 1–2 个接壤的内环区域进入，两个时挑方向相距最远的一组 |
| 6 | 锚点 `placeAnchors` | 图 → 入口、撤离点 A/B/C | 入口取外环上离首领殿最远、且靠近屏幕下方的区域；A 离入口约外环 1/3 圈；B 同时远离入口和 A；C 在中环、离 A/B 远且尽量深；窗口按种子 ±2 步浮动 |
| 7 | 事件 `placeEvents` | 罗盘 → 事件模板落点 | 模板有四种形态，见 §4 |
| 8 | 房间 `fillRooms` | 配额表 → 每个区域的房间类型 | 先把各类放到下限，再按权重补到上限；约束见 §3 |
| 9 | 巡逻 `placePatrols` | 图 → 游荡敌人的路线 | 在外环或中环上取 3–5 个连续区域来回走，路线互不重叠，起点离入口 ≥ 2 步 |
| 10 | 冰潮 `placeTide` | 图 + 撤离点 → 每个区域在第几次冰潮被封 | 见 §2.2 |
| 11 | 通道位置 `placeDoors` | 图 → 每条通道的门 | 门画在共享边界的中点；相邻但没开通道的共享边界（≥ 6px）输出成墙 |
| 12 | 标记居中 `centerSites` | 区域 → 标记位置 | 把标记和地名从站点挪向区域形心，依次试 100% / 75% / 50% / 25%，取第一个落在区域内、也在安全区内的位置。区域形状不变 |
| 13 | 校验 `validate` | 整张图 → 通过 / 错误列表 | 见 §5；不通过回到第 1 步，尝试号 +1，最多 40 次 |
| 14 | 装配 `dressRooms` | 区域 → 房间内容 | 每个房间用 `种子 | 节点 id` 自己的随机流生成敌人队伍、掉落（`rw`：图标、名称、说明）、神龛选项；见 §6 |
| 15 | 地名 `namePlaces` | 区域 → 地名 | 按层从群系地名表里不重复地抽（霜渊：第一层 12 个、第二层 10 个、第三层 5 个），首领殿固定叫“冰封王座”，金库口袋用自己的一组名字 |

“谁和谁相邻”由区域切分决定，“相邻里哪些能走”由第 5 步的环规则决定，所以 `01` §4.1 的三环拓扑不变：外环成环、中环和内环有缺口、首领殿只有 1–2 个入口。

### 2.1 外形

三环表示深度，不画成正圆。每张图用独立的随机流 `shape` 抽一个外形，站点位置跟着变，切出来的区域轮廓也就每张图不同：

- 首领殿偏离中心：方向在“正上方 ±108°”里抽，偏移量为外环半径的 16%–32%。多数图首领殿在远处，也有明显偏左、偏右的。
- 漏斗：各环的环心朝首领殿偏移，外环 0、中环 50%、内环 92%。外侧一圈宽、靠首领殿的一侧窄，看起来是往一边陷下去的深渊。
- 低频起伏：半径乘 `1 + a2·cos 2θ + a3·cos 3θ`（a2 0.06–0.16，a3 0–0.08；中环 ×0.85、内环 ×0.55 减弱），得到腰形、肾形、圆角三角形等轮廓。
- 螺旋：沿环一圈半径线性渐变 ±6%。
- 入口落在首领殿对面，所以入口在屏幕上的位置也随种子变（底部、左下、右下、左侧都会出现）。

连线只看节点在各自环上的角度顺序，外形变化不改变 `01` §4.1 的拓扑规则。

安全区：站点（标记）横向 120–1480、纵向 176–800；底部两个角（x < 420 是队伍栏，x > 1130 是道具栏）站点不低于 730。区域本身可以延伸到屏幕边缘，只是标记和地名不进这几块地方。

### 2.2 冰潮（后台计时）

步数只在服务端记，界面上任何地方都不出现数字或进度条。服务端按动作累加：走一格 1，搜刮（第一次）按房间定，战斗 2，营火 3，烟雾弹 1。神龛“缓潮”把后台步数退回 3 步，下一次冰潮就晚 3 步；最多退到上一次冰潮刚涨完的时候，已经封住的区域不会解封。

每隔 `tideEvery` 步（标准 6、短途 4）冰潮上涨一次，一共 `总步数 / tideEvery` 次（两种都是 6 次）。第 10 步按种子排好每个区域在第几次冰潮被封：

1. 撤离点 A、B、C 依次在倒数第三、倒数第二、最后一次冰潮时封住；撤离窗口的结束改成那一次冰潮的前一步，开放时间不变。
2. 第一层和第二层的普通区域按递增权重分批：第 k 次的权重是 `2 + floor(2.2 × (k − 1) / (次数 − 2))`，每次至少封 1 个。第二层从第 `min(2, 次数 − 3)` 次起进入候选。
3. 候选里先挑第一层，再挑紧挨着已封区域的，所以冰潮是一片一片推过去的。每封一个都检查剩下的区域没有被切成更多块。
4. 一个都封不了时（剩下的都是必经之路），允许切下一小块：不超过 3 个区域，里面没有首领殿，也没有之后还开着的撤离点。这一小块和撤离点切出去的孤块一起在这次被吞掉，下一次相应少封几个（仍至少 1 个）。
5. 第三层和渊底在最后一次冰潮一起封住。最后一次冰潮时还在图里，这一趟算失败。

玩家站的区域被封时，会被推到最近的未封区域，全队失去 15% 生命。距离相同时依次优先：不在下一批里的、没有游荡敌人的、直线距离近的。

界面只用画面表达时间（`05` U14）：下一批要封的区域画紫色双虚线，越接近涨潮，区域内侧的霜边越宽，临近时虚线加速并有一句轻提示；整局进度画成地图外轮廓上一圈越来越宽的霜边；已封的区域盖白色冰面。

200 张图的统计（`node .tmp/tide-check.cjs 200`）：

| 指标 | 标准 | 短途 |
| --- | --- | --- |
| 每次冰潮平均封住（第 1–6 次） | 2 / 2 / 3 / 3.8 / 4.3 / 6.4 | 1.2 / 1.7 / 1.5 / 3.4 / 3.9 / 4.8 |
| 一次都没封的冰潮 | 0 | 0 |
| 剩下的区域被切断 / 撤离点全封 | 0 / 0 | 0 / 0 |

短途图区域少，前三次的数量不完全递增（第 3 次比第 2 次少 0.2），玩家感受不到差别，暂不处理。

### 2.3 分层

三个环对应往下的三层，首领殿是渊底。层只影响表现，不改 `01` §4.1 的拓扑：

- 每层一个层名，顶栏显示“第二层 · 极光冰窟”这种格式。
- 每层一张地面贴图，层和层的交界画成往下的台阶（§7）。
- 地名按层抽，地名决定地标贴图。
- 冰潮从第一层往下涨（§2.2），第一次进入第二层、冰潮第一次漫进某一层时各有一句播报。

## 4. 事件模板

| 形态 | 做法 | 例子 |
| --- | --- | --- |
| 单点 | 在指定环上挑一个空节点作为事件核心 | 魔方（内环） |
| 点 + 范围 | 核心 + 有通道相连的区域构成范围；先在范围里占住 N 个战斗房间，算进驻守配额 | 血祭：祭坛在中环或内环，离入口 ≥ 2 步；范围里至少 2 个战斗房间，名单才填得起来（`02` §1.1） |
| 改配额 | 不占节点，只改第 5 步的配额 | 劲敌：稀有怪巢 +2，驻守 −2（地图大小不变，`01` §2.2） |
| 口袋子区 | 在核心旁挂一串新节点，只能经核心进出 | 金库：金库门 + 3–5 个保险柜、机关、守卫（`02` §6.1） |

- 核心优先选“相邻空节点最多”的位置，给范围和口袋留地方。
- 每个罗盘阶对应模板参数（祭坛数、名单上限、口袋大小），按 `02` 各节的罗盘表取值。
- 新事件上线时只需要新增一个模板，不改前面的步骤。

## 5. 校验

每张图必须同时满足：

1. 全图连通。
2. 入口到首领殿 ≤ 总步数 / 4（标准图 ≤ 9 步，短途 ≤ 6 步）。
3. 每个撤离点从入口出发，能在窗口关闭前 2 步走到；撤离点两两间隔不小于 §3 的值。
4. 两个领主巢不相邻。
5. 血祭范围里至少 2 个战斗房间。
6. 外环相邻的区域两两接壤，且共享边界够开通道（第 5 步发现断开就直接重试）；首领殿至少和一个内环区域接壤。
7. 每条通道都落在一段 ≥ 44px 的共享边界上（`通道无边界`）。
8. 每块区域面积 ≥ 11000px²，首领殿 ≥ 17600px²（`区域太小`），保证放得下地名、标记和地貌。
9. 标记不互相压住（`标记重叠`）：每个区域的标记 + 地名按 80×60 的框算，撤离点在下方再加一条 176×24 的撤离标签，任意两个框重叠就重试。
10. 领主、群系专属节点、标准图营火的数量达到下限。

1000 个种子的批量结果（生成器第 4 版，`node .tmp/mapgen-check.cjs 1000`，罗盘为血祭 + 劲敌，日志在 `.tmp/exp-v6/mapgen-1000.log`）：

| 指标 | 标准 | 短途 |
| --- | --- | --- |
| 同种子重复生成完全一致 | 20 / 20 | 20 / 20 |
| 第一次尝试就通过 | 64% | 58% |
| 最多重试次数 | 12（只有 1 张图） | 9（只有 1 张图） |
| 最终仍失败 | 0 | 0 |
| 节点数（含首领殿） | 20–23 | 15–18 |
| 入口到首领殿 | 3–8 步，多数 5 步 | 3–6 步，多数 5–6 步 |
| 配额缺口 | 补给箱 38%、宝箱 18% 的图低于下限 | 稀有怪巢 10%、补给箱 8% |

重试原因（1000 张图里累计出现的次数）：

| 原因 | 标准 | 短途 |
| --- | --- | --- |
| 外环断开 | 278 | 490 |
| 撤离点来不及 / 太近 | 236 | 0 |
| 首领殿太远 | 0 | 132 |
| 标记重叠 | 87 | 21 |
| 血祭范围战斗不足 | 0 | 50 |
| 区域太小 | 6 | 32 |
| 首领殿不接壤内环 | 0 | 4 |
| 缺少房间 | 3 | 2 |

冰潮排期（第 10 步）本身不会让图校验失败。版本号是随机流的一部分，换成第 4 版后同一个种子生成的图都变了，所以这些数字和第 3 版有小幅出入。

短途图节点少、每块区域大，外环相邻区域更容易被中环隔开，所以“外环断开”是主要重试原因。重试只在生成时多花几毫秒，不影响玩家；如果以后要压低重试，优先给 `repairRim` 多几轮，而不是放宽外环成环的规则。

标准图的配额缺口来自节点数上限：领主、事件、劲敌加出来的怪巢先占了位置。如果模拟显示补给不足，优先把外环节点数调到 10–11，而不是砍事件。

## 6. 房间装配

- 驻守：4 名敌人，每名按环位抽怪物稀有度（外环 普通 60 / 精良 32 / 稀有 8；中环 35 / 43 / 22；内环 15 / 45 / 40），稀有度决定词缀条数（0 / 1 / 2）。
- 稀有怪巢：前 2 名稀有、后 2 名精良。
- 领主：按群系的领主表依次取，领主本体 + 固定的 3 名护卫（`03` §8.3）。
- 首领：群系首领 + 3 名稀有护卫。
- 掉落：按环位倍率（外 1.0 / 中 1.3 / 内 1.7，`01` §3.4）提高高品质的权重；上锁宝箱和冰封棺第一件至少稀有。
- 敌人从群系池里抽，正式实现接 `03` §1 的出敌流程（协同评分组队、种族倾向词缀）；原型里用一张寒冬堡垒的小表代替。
- 装配结果写进 run 状态。掉落的实际入账仍然以战斗结算为准（`docs/battle-settlement-rewards.md`），结算页不重新抽奖。

## 7. 画面组装

区域每张图都不一样，固定构图的插画对不上，所以底图按种子现画。画面分两层：

**底图（Canvas 2D，`expedition_terrain.js` 第 4 版）**：每张图只画一次（种子或出征类型变了才重画），同一张图每次画出来都一样。画风和营地一致（`scripts/art-gen/expeditionAbyssAssets.mjs` 出的 `abyss/*` 贴图），不用写实俯视，也不压暗。

- 深渊外面：偏亮的蓝紫暮色加雾团和雪尘。高原外轮廓往下错开 4 层画出悬崖厚度。
- 地面：每块区域裁出它所在那一层的地面贴图（`w1-ground` 雪林、`w2-ground` 极光冰窟、`w3-ground` 巨人冰冢，渊底沿用第三层）。贴图做成 2×2 镜像后平铺，看不出接缝；越深的层叠一层偏紫的色调。
- 层间台阶：不同层的交界，深的一侧沿边界压三道渐淡的阴影（宽 60 / 32 / 13px），浅的一侧先画一道 8px 深色断面，再叠一道雪檐亮边。一眼能看出往下走了一级。
- 冰裂缝：同一层里相邻但不开通道的边界画成锯齿冰裂缝，表示过不去。
- 小径：每条通道画一条雪地小径，从区域中心经门走到另一边的中心；跨层的通道口画三道冰阶。
- 地标：每个地点按地名放一个地标贴图（`w-*`，共 16 张），贴在地面上，不做成浮岛。地名和地标的对应表在 `expedition_terrain.js` 的 `KIND`。

**状态层（SVG）**：只画会随玩家行动变化的东西。

- 区域轮廓：细白线；当前区域、可走到的区域、选中的区域各有高亮；撤离区域淡绿，首领殿淡红。
- 迷雾：没看清的区域盖一层雾纹，标记位置画两道雾线代替问号，地名牌变暗、边框改虚线。地形和区域划分一开始就能看到，房间内容看不到。开局能看清入口、撤离点、首领殿和罗盘事件；之后走进去或走到相邻区域才能看清。
- 冰潮：已封的区域盖白色冰面纹理；下一批要封的画紫色双虚线和向内长的霜边；地图外轮廓的霜边随整局进度变宽（§2.2）。
- 通道口：两端都看清了才画门的小圆点。
- 标记和地名：每个区域一个类型标记（深色圆底 + 彩色线条图形，只有撤离点和首领殿是实心）加地名；撤离点下方挂一条绿色撤离标签，状态为“稍后开放 / 可撤离 / 冰潮将至 / 快封了 / 最后的出路 / 已封闭”，不写步数。标记不拦截点击，点在标记上等于点这块区域。
- 路线：选中一块区域后，画出经过各个门的最短路线（不穿过已封的区域）。
- 游荡敌人：看清了所在区域就显示头像。

其他深渊（§2.4）沿用同一套底图流程，只换地面、地标和封区纹理。旧版的写实贴图（`xt-*`）和卡通贴图（`anime/*`）都保留在仓库里，不再使用的也不删。
