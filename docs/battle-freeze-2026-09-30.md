# 战斗间歇卡住 / 宝石停在压扁状态排查（2026-09-30）

## 已复现的故障

在同一浏览器页面里，启动真实战斗 App → 显示提示 → 切到 2× → 清除提示 → 销毁战斗 → 新建下一场战斗。

修复前，浏览器在短时间内出现 94 次未捕获异常：Pixi Container 已销毁，旧 GSAP 补间仍执行位置写入，抛出 `Cannot set properties of null (setting 'y')`。红灯日志为 `artifacts/battle-reentry-red.log`。此场景不需要慢网络。

根因在 `battleSpeedRuntime.ts`：缓存了无限循环动画的基准速率，但仅在后续 RAF 清除已脱离时间线的条目。切倍速/离开战斗时调用缓存对象的 `timeScale()`，可能将已经 kill 的补间重新挂回旧父时间线。尚在 delay 阶段、没有初始化的提示动画随后访问已销毁的精灵，反复打断动画更新。

正常落地效果暂时把宝石缩放到最多横向 1.12、纵向 0.84，再恢复正常比例。动画更新被异常打断，与“偶尔动一下、宝石变宽、拖不动”的现象相符；未取得用户出问题时的线上运行栈，因此不把这一条复现等同于该次线上事故的唯一原因。

此外，补查状态宝石粒子时发现独立的清理遗漏：`GemSprite` 原先没有销毁覆写，Pixi 子节点销毁后 GSAP 粒子循环仍存在；对象池回收也只停止宝石自身及 scale 补间，没停子级粒子。实际 GSAP/Pixi 单测复现销毁后时间线推进抛 `Cannot read properties of null (reading 'y')`，以及回收后仍有两条粒子循环。红灯日志 `artifacts/gem-lifecycle-red.log`（2 项失败）。这一条并不要求切倍速。

## 修改

- 在调整循环动画速率之前，同步剔除已经脱离全局时间线的动画，不再等后续 RAF。
- 最后一个战斗解绑时，同样先清理失效引用，再还原存活循环速率，避免旧提示/待机动画复活。
- App 销毁时先释放输入控制器（指针跟随、捕获与事件监听）并停止待机/提示，再解绑倍速与销毁 Pixi 对象。
- 补齐风暴指示器销毁，释放其定时器和 DOM 动画。
- 宝石最终销毁与对象池回收/复用统一停止自身、scale 和状态粒子动画；先停补间再销毁 Pixi 子节点，复用后只建立新类型需要的粒子。
- 保留正常落地回弹、提示呼吸及倍速效果，没有用强制解锁输入掩盖未完成动画。

## 回归覆盖

`tests/unit/battleSpeedLifecycle.test.ts` 使用实际 GSAP 和 Pixi Container，覆盖：

1. 切换倍速不重新挂回已 kill 的无限动画。
2. 退出战斗还原速率不复活旧动画。
3. 延迟补间目标已销毁后，全局时间线推进不再访问该目标。
4. 活跃循环维持原速，有限动画仍按倍速播放。

`tests/unit/gemAnimationLifecycle.test.ts` 使用实际宝石精灵/对象池与 GSAP（仅贴图替换为空纹理），覆盖状态宝石销毁后时间线推进、池内粒子停止，以及普通骷髅/状态宝石反复复用。

`tests/e2e/battleResponsiveness.spec.ts` 使用真实浏览器和战斗渲染，覆盖：

- 资源加载完后断网，主线程每 200ms 忙等 160ms，自动战斗运行 25 秒。断言实际产生交换，演出完成，输入恢复；再实际鼠标拖拽合法交换。
- 同页连续三次退出/重建战斗，退出前制造 2× 下的延迟提示动画，三轮分别测试仅提示、仍在场的燃烧粒子、回收进池的中毒粒子；每场都实际鼠标拖拽，验证交换执行。
- 输入恢复时有限视觉任务归零、播放器停止、棋盘宝石横纵比例一致；捕获并断言没有浏览器未捕获异常。

离线用例在断网前下载测试辅助模块，不通过网络重新载入战斗。上述用例不覆盖真实 Discord 登录、线上签票/结算或所有设备性能情况。

## 网络边界

- `App.handleSwap()` 调用本地 session resolve 并播放动画，普通逐步交换没有等待远端存档请求。
- 登录、资源预加载、出战签票及战后结算涉及另一条网络路径。此前冷加载慢的问题不等同于本次动画帧异常。
- 当前证据不足以把战斗冻结归因于域名、Cloudflare 或存储；本次修复也不声称排除全部网络问题。
