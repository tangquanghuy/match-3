## 先纠正之前 191 秒的代表性

之前线上验收的 191 秒是自动化测试机上的冷启动样本，不是线上用户的总体分位数。这台 Windows 机器启用了系统 HTTP 代理（本机回环端点）。默认 Chromium 沿代理线路访问 Cloudflare 香港节点；curl 的直连样本则返回伦敦节点标记。二者不是同一路径，不能直接混用其耗时归因。

此次完整浏览器复测记录：

- 默认代理线路、HTTP/2、冷启动 **197.973 秒**；607 个同源资源条目，网络传输统计约 **54,698,819 字节**。
- 页面建立连接约 **1.543 秒**，发出请求至首页首字节约 **0.392 秒**；绝大部分时间发生在首页收到后的资源阶段。
- 同源资源 TTFB 中位数约 **1,286ms**、P95 约 **4,454ms**；响应体阶段中位数约 **210ms**、P95 约 **928ms**。TTFB 包含网络/代理等等待，不等同于 Cloudflare CPU 或存储耗时。
- 响应标记中 607 个 `CF-Cache-Status: HIT`，节点后缀为 HKG；身份请求 401 和 trace/浏览器辅助请求不属于静态缓存断言。
- curl 单独进程的 DNS 样本为毫秒级；其连接/TLS/下载结果只代表直连路径。首次完整浏览器 Resource Timing 中 DNS 为零长度，可能已复用解析，不将其解释为所有用户 DNS 都是零延迟。

## 应用自身的负担

部署基线的清单有 **55 个代码文件 + 537 个图片/音频文件**，磁盘体积共 **60,739,238 字节（57.93 MiB）**。代码约 8.04 MB，图片/音频约 52.70 MB。实际传输体积与磁盘大小不同，代码受到 HTTP 压缩。

当前预加载器固定 **6 路并发**，且要整个清单成功后才开放登录；其中包含世界地图、战斗特效、音效等，不只是建角页。三张主角 WebP 合计 **403,008 字节**，并非这 58 MiB 的主要来源。逐资源的延迟会在约百批请求中累积，低并发和大清单放大线路延迟。

尚不支持「换域名即可解决」或「Cloudflare 平台整体故障」的判断。缓存命中也不代表客户端到节点的路径必然快；静态资源加载问题与领取馈赠的 DO 存储耗时需分开看。

## 对照实验

相同线上清单均匀抽取 96 个图片/音频（响应体总大小 9,036,869 字节），使用独立空缓存浏览器上下文，分别比较系统代理/浏览器显式直连与 6/18 路并发；不改系统代理开关，不操作玩家数据。

| 浏览器路径 | 并发数 | 96 个资源读完 | 结果 |
| --- | ---: | ---: | --- |
| 默认系统代理 | 6 | 22.441 秒 | 96 个 HIT，0 失败 |
| `--no-proxy-server` | 6 | 29.990 秒 | 96 个 HIT，0 失败 |
| `--no-proxy-server` | 18 | 21.208 秒 | 96 个 HIT，0 失败 |
| 默认系统代理 | 18 | 4.605 秒 | 96 个 HIT，0 失败 |

四组都是 HTTP/2、HKG 标记、实际网络传输（非浏览器缓存）。浏览器显式直连仍到 HKG，与 curl 的 LHR 不同；传输栈、DNS/路由和测试时间存在差异，因此不拿 curl 和 Chromium 的数值做纯代理效果比较。

这是按上表顺序执行的一轮小样本，未做多轮随机交叉，线路波动、浏览器连接状态等仍可能影响结果。它支持「提高并发值得优化和复测」，不支持保证全量加载会缩短到同样秒数。**显式直连没有消除慢加载，现有结果不支持把问题全部归因于代理。**

额外的再次访问试验也没有证明稳定命中完整浏览器缓存：同 URL 再访问仍传输了约 54.5 MB；换入口查询串的再次访问在 300 秒等待内未出现就绪状态，该轮脚本未保存失败时完整资源状态，不将超时解释成已经定位某个具体资源故障。此为测试上下文的观察，尚未核实普通持久浏览器配置下的缓存行为。

## 建议的优化顺序（本轮尚未改预加载代码）

1. 保留用户要求的「全部必需资源成功后才开放进入」，不恢复跳过加载。
2. 先在目标用户网络上多轮验证并发 12/18 与 6 的全量对照，记录超时和失败率，再选择并发上限；本轮只做诊断，不直接把单次小样本最优值发布。
3. 减少字节数和往返次数：压缩较大的音效、地图和特效资源，核对清单中非必需项目，但是否拆分非首屏资源需要明确产品边界，不能通过偷偷绕过现有加载门槛实现。
4. 使用真实持久浏览器验证缓存复用，避免仅凭 Cache-Control 头或自动化临时上下文下结论。
5. 暂无证据需要先换域名或更换 CDN。若优化后仍慢，再在实际玩家地区/运营商做相同资源的线路对照，区分节点覆盖与本地代理/ISP 链路。
