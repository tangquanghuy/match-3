# 藏宝图：自然随机与单一区间软上限

日期：2026-10-01。状态：已实现，未提交、未部署。

## 单一随机目标

不是“红箱门槛”和“宝库门槛”各抽一次，也没有两者择一触发。

- 红色宝箱（tier 6）计1点，宝库（金库，tier 7）计3点。
- 每局只在整数区间 **3～9** 均匀抽取一个目标，对应约3个红箱至3个宝库。
- 混合盘面共同计入这个目标：例如目标7，需要2宝库+1红箱，或1宝库+4红箱等。
- 记录本局达到过的**最高盘面等价值**。3红箱升级为1宝库仍是3点，不把生成次数相加算成6点。4/5红箱升级后保留先前峰值，不撤销已触发的状态。
- 初级宝物不贡献这个进度。上限不是奖励封顶；之后仍可继续合成、获得宝库。

## 匹配倾向

普通战斗的 `BATTLE_COMBO_BIAS=5`、开局择盘参数保持原状；藏宝图完全不接入这条生成链。

- 开局仅排除已有三连及死盘，采用首个可走棋盘，不按四/五连机会择优。
- 软上限前匹配偏置为0，每个空位一次自然抽取；原补充分布72/22/5/1不变。
- 达标后偏置从-1开始，每3次有效操作再降低一级，最多-5；超出目标每2点也会提高一级降温强度。
- 负向补充降低相邻同种宝物权重，再在最多11个候选中优先选择自动连锁更少、后续四/五连机会更少的补充结果。
- 只决定新补充的低阶宝物，保留现有棋子、宝库和已完成的升级。四连不耗步、五连加一步、已有步数及结算奖励逻辑保持原状。
- 没有新增强制结束条件，也没有把模拟测试的操作次数上限用于游戏运行时。

## 持久化与兼容

`TreasureHuntState.softCap` 记录 `target / peak / activeMoves`；开始、提交操作、客户端结果和读档均保留。

随机目标使用独立确定性随机流，不额外消耗开局或基础补充随机数。刷新、离开后返回不重抽目标；无效交换不增加降温进度。旧局读档时根据当时盘面补齐一次；历史上已消失且旧档未记录的盘面不追溯。

## 验证范围

- 单一区间覆盖、固定种子确定性、混合宝物、升级不重复计分、峰值保持、渐进负偏置。
- 触发前的独立自然随机与不送开局四/五连。
- 读档连续性、无效操作不改状态、四/五连仍奖励步数、负向补充的事件重放与宝库保留。
- 浏览器真实提交一步后刷新，核对目标与降温进度不丢失。
- 固定20个种子的贪心玩家模拟（优先可见额外回合，不预知补充）：软上限版本20局均自然结束；每局最多1200次操作的对照观察中，无降温版本仅6局结束。此为确定性回归样本，不是对所有种子或所有玩家的结束步数保证。
- 样本中触发后的四/五连奖励回合占比由约66.3%降至37.4%；软上限版本平均445.85次操作，最长636次。前期已经攒下的步数不直接扣除，因此达到目标不代表立即结束。
