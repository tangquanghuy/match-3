# BGM 资产与接入说明

## 资产

从用户指定的 `C:\Users\Administrator\Downloads` 导入 11 首已命名曲目，成品位于 `src/assets/audio/bgm/`。下载目录原文件保持不变；未导入旧的捕鱼、老虎机音乐，也未改动旁白文件。

- `menu-01/02.mp3`：主界面 1 / 2。
- `map.mp3`：地图。
- `preparation.mp3`：部队准备。
- `events.mp3`：活动。
- `battle-01/02.mp3`：普通战斗 1 / 2。
- `elite-01/02.mp3`：精英战斗 1 / 2。
- `boss-01/02.mp3`：首领战 1 / 2。

`manifest.json` 记录原文件名、源 SHA-256、边界裁剪量、成品时长、实测响度、峰值与大小。再导入命令：

```powershell
python scripts/import-bgm.py --source 'C:\Users\Administrator\Downloads'
```

处理为 44.1kHz / 双声道 / 128kbps MP3；两遍响度匹配目标 -17 LUFS、峰值上限 -3 dBTP。转码后 11 首实测为 -17.46 至 -17.33 LUFS，比上一版提高 5.97–6.10 dB，真峰值均低于 -3 dBTP（逐曲数据见 manifest.json），避免原曲响度不同导致换歌突然变响。只裁首尾检测出的静音，保留内部乐句及停顿；首尾追加极短防咔哒包络。未做变速、变调或重编曲。

## 触发规则

选择函数与曲库：`src/audio/MusicCatalog.ts`。

| 音乐场景 | 曲目 | 触发 |
| --- | --- | --- |
| 非战斗 | menu-01/02、map、preparation、events，共 5 首 | 首页、地图、编队、英雄、商店、活动等全部普通页面共用一个曲库 |
| 普通战斗 | battle-01/02，共 2 首 | 敌方无精英/首领标记的战斗 |
| 精英战斗 | elite-01/02，共 2 首 | 敌方精英、塔目标，或 PvP（竞技场/入侵） |
| 首领战 | boss-01/02，共 2 首 | 敌方首领/领主/传奇，或显式活动 boss 目标；优先于 PvP |

11 首全部保留使用，只合并音乐场景，不减少曲目。设置页和战后 meta 结算页保留已有音乐。

- 普通页面之间快速或慢速切换都不换歌、不重新选曲，保留同一媒体元素与播放进度。打开活动页也不单独切活动曲。
- 首次播放、真正跨音乐场景进入、当前曲目自然播完时，从对应曲库随机选曲。每组使用 Fisher–Yates 随机洗牌袋，一轮内每首播放一次，下一轮开头避开上一首；两首的战斗组随机起始后交替，兼顾随机和不连续重复。
- 使用独立的音乐随机入口，不消耗战斗随机数。播放暂停、音量调整、页面隐藏/返回都不抽新曲。
- 真正离开音乐场景再回来时，重新随机选曲并从新曲开头播放；这和普通页面切换、浏览器后台恢复是不同的行为。
- 战斗曲只在入场时按敌方快照选择。连击、施法、受击、地精出现、召唤、首领阵亡等都不改曲；后台路由不覆盖战斗音乐。
- 结算面板保留当前战斗曲并压低；退出战斗后等待 700ms 再回非战斗音乐。若期间进入下一场战斗，取消这次返回；同类连续战斗续播原曲，不插入菜单音乐，不因开局反复抽歌。

## 存在感与混音

不覆盖玩家现有偏好。默认主音量 80%、音乐 50% 保持不变；实际还乘独立曲目增益：

| 场景 | 曲目增益 | 默认设置下媒体音量 |
| --- | --- | --- |
| 主界面 | 0.825 | 33% |
| 地图 / 准备 | 0.75 | 30% |
| 活动 | 0.72 | 28.8% |
| 普通战斗 | 0.975 | 39% |
| 精英战斗 | 0.90 | 36% |
| 首领战 | 0.825 | 33% |

根据实际游戏反馈，所有场景增益统一提高为首次接入时的 1.5 倍（约 +3.5 dB），不覆盖已保存的音量滑杆。

第二次音量反馈后，从下载目录原文件重新制作，素材响度目标从 -23 提高至 -17 LUFS，约再提高 6 dB，避免重复压制旧 MP3；保留上述运行时增益、玩家音量偏好及旁白压低比例。首领曲不靠额外抬高音量营造史诗感。

- 真正开始播旁白时，音乐再降到平时 **28%**，约 200ms 压下；旁白结束/取消后约 1.5 秒内缓慢恢复。下载中尚未发声不压低音乐。
- 战斗设置打开时保留 **55%**；战斗结束/放弃后的结果阶段暂停 BGM（增益 **0%**），结算页不切换到菜单音乐。
- 多种压低原因并存时取最低增益，不连续相乘。关闭设置不会抹掉尚在生效的结算/旁白压低。
- 调整主音量/音乐音量即时生效。关闭音效或旁白不会关掉音乐。主开关或音乐开关关闭时立即暂停。

## 衔接与生命周期

`BackgroundMusic.ts` 最多保留两个流式媒体元素，不把全部 BGM 解码常驻内存。

- 首次鼠标/触摸/键盘交互后按需加载；没有交互时不请求音频。
- 初次播放约 2.2 秒淡入；场景间约 2.2 秒线性交叉淡化，避免叠加变响。
- 曲尾提前 3 秒启动下一首（单曲场景从同曲开头接回），使用交叉淡化而非硬切文件尾。媒体结束事件另有兜底。
- 此处是听感衔接，不声称所有生成曲天然满足节拍/和声无缝；原有长铺垫/结尾仍保留，后续可以基于实际听感进一步定制循环点。
- 后台页面立即暂停，显式记录曲目和时间；返回时恢复进度并柔和淡入。重复隐藏/静音事件不覆盖原检查点，媒体加载完成后再恢复位置；静音期间不创建新曲。
- 各音乐场景保存生命周期检查点；普通菜单切换不中断播放，浏览器后台返回不从片头重新开始。真正跨游戏音乐场景时按上述随机规则选新曲，不恢复上一次入场的旧进度。浏览器当前标签页的 sessionStorage 保存检查点（每 5 秒及切场景/离开页面时更新），支持浏览器前进/后退、刷新或页面重建后续播；存储受限时仍保留内存中的续播能力。新文档继续遵守首次手势解锁。
- 快速切出/切回打断尚未完成的 play() 时，区分暂停引起的 AbortError 与真实播放错误，自动续播而非等待第二次点击。
- 解锁失败等下次用户手势再尝试；资源错误不循环疯狂重试；销毁会清理媒体、监听器、路由延时和混音定时器。

## 验证

- 单元测试：曲库数量、页面/战斗分流、渐变、双声部上限、随机洗牌覆盖全部曲目及跨轮防重复、各路独立音量、叠加压低、隐藏/静音恢复、错误/异步销毁、战斗优先、普通导航续播和连续战斗返回防抖。
- 浏览器：11 首实际 AudioContext 解码；快速及慢速切换主界面、编队、活动、英雄、商店时持续播放，设置静音/恢复；战斗设置、真实旁白联动、放弃结算与退出恢复。
- 旧宝箱音效测试只观察音效资源，背景音乐是独立通道，不应被“关闭音效”断言算入。





## 结算阶段衔接

- 已结束战斗销毁时，音效停止，正在播放的胜利/战败/撤退语音由独立音频生命周期收尾；结算页保持音乐暂停。
- 离开结算页后恢复对应场景音乐；开始新战斗会清理上一场残留语音，避免叠播。
- 结算界面仅显示本场经验、金币、灵魂及实际战斗宝石收入。首胜、首通、任务、周常和竞技场整轮奖励不混入本场收益；这些系统的发奖规则保持原样。
