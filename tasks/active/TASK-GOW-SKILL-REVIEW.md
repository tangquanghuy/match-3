## 目标与边界

逐一核对并验收仓库内原版 **2,518 项技能实体：1,800 名部队 + 718 件武器**。自设 13 项另列，不混入原版签收。以保存的英文描述和原始 `SpellSteps` 为当前比对基线；本项目结论是**针对该来源快照**的一致性验收，不冒充 GoW 当前线上版本认证。用户已裁定的未实现模式、晋升度依赖以**具体子句／步骤**登记排除，不扩散到整项。散射精确随机、风暴掉率、狼化掷签顺序和已有两项裁定冲突仍按已记录现状处理；任何新证据再单独核议。

现有机器可核形状与真实施法测试只用于发现缺陷、减少重复工作；**整项签收必须逐实体逐子句／原始步骤／分支落实 12 维证据，并有当前指纹的全量验证凭证**。

## 工作计划（保持同一条主线，不启用历史任务）

1. **冻结基线、重建索引**：记录原始快照来源与指纹；运行全量验证、总账、队列、同构组和机制族索引；校验数量、重复 key 和武器 `gw_` 注册。产物为可追踪的 2,518 个实体队列。
2. **先查共用原语**：目标选择／隐匿／死亡后重选、伤害（普通／真伤／轻重溅射／散射）、状态免疫与持续时间、特殊宝石创造／匹配／摧毁／爆破、法力与回合、条件／概率／分支、召唤与属性。每项核源码、共享规则证据与实际回归；差异先修公共机制，再定位受影响实体回归。未知原版算法依现有裁定，不臆造精确值。
3. **同构批次复核**：优先处理剩余溅射／散射多段及两个已确认差异，再处理死亡触发／多段目标／概率分支／特殊宝石／法力与额外回合等高风险组；按原版有序步骤形态和组装器原语聚类，共享检查一次、变量逐项核一次。每组至少覆盖边界、负例、双方、固定种子，再针对差异项补场景。
4. **逐实体签收**：逐行核英文文本、费用／颜色／身份、每个原始步骤及选项分支与最终注册原型；运行 `TurnEngine.castSkill` 的实际战斗测试；填齐 12 维、英文子句、原始步骤和分支证据。将审过但有缺口的行保留 `draft`；修复并复测后才写 `accept`。
5. **持续封账**：每批按指纹执行全量验证、重建账本和队列，定量报告新签收、未决、真实差异、待来源裁定；直到 2,518 项逐项有合法结论，零未解释差异，当前指纹全量测试与类型检查通过。禁止把全量跑通叫作全量验收。

**单批闭环**：取同构组 → 原文／原始步骤／最终原型三方对照 → 自动找参数差异 → 真实施法断言 → 修复与回归 → 完整证据 → `accept` → 当前指纹全量验证 → 核实签收增量；未满足则标记缺口转下一批，不阻塞其他可核项。
