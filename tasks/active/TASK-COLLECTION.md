## 2. 批次

### 批次 0 · CH-1 资源损失热修（**最高优先，独立提交**）

**现象**（复核实测，`u4-gold10-verify.log`）：钥匙 7 把点「开启十次」→ `keysSave 7 → 0`（扣光）、`collection` +5 条 / 副本 +2（**7 张卡确实入账并已持久化**）、**演出没开**、最近获得条 0 条、toast 反而报「金钥匙不足：需要 1，现有 0」、`dockKeyUi`/`topbarKeyUi` 仍显示 **7**（切页才变 0）。按钮 `btnTitle:"货币不足"` 但 `btnDisabled:false` → 这一步玩家必踩。

**根因两处**：`chestsScreen.ts:265-270` 把 `gold-10` 实现成"循环 10 次单抽"，第 8 次失败 `return null`，把前 7 次**已 persist**（`mockGateway.ts:236-244`）的结果整块丢弃；`:287-300` 失败分支不走余额刷新与最近获得条；禁用缺口在 `:203-211`。

**修法（三件一起做）**：
1. `gateway.openChest` 支持 **`count` 原子批量**（要么十连整批成交，要么一张不动）；
2. 余额不足时按钮 `disabled` 且文案改「还差 3 把」（顺带修 CH-4：五个按钮买不起照样可点）；
3. 失败分支也必须 `refreshBalances()`，并对"钥匙只够 7 抽"给明确选择（开 7 次 / 取消），不允许静默。
4. 单测锁：余额 7 开十连 → 要么 0 消耗 0 入账，要么 7 消耗 7 入账 + 演出 + 最近获得条 7 条；**不允许出现"扣了但没演出"的中间态**。

## 3. 验收标准

1. **CH-1 关闭**：单测 + 手测，余额不足的十连不再出现"扣了但没演出"；按钮态与余额一致。
2. **图鉴可用且立绘清晰**：浏览卡至少 70% 高度留给画作，姓名/等级在不压图的单行底边；未获得卡仍能辨认主体；数值在详情可查。取消「85 张 ≤3 屏」指标。「全部」分段渲染，排序、滚动复位、编队出口和详情箭头行为保持通过。
3. **编队可用且立绘清晰**：四个槽位和名册以画作占主要面积，选中详情承载数值/技能；站位可调（`⇅`/`✕`）；选中态可辨；仅校验异常常驻；旗帜选择器不遮槽位且 Esc 可关。桌面与窄屏截图均检查人物主体无遮挡。
4. **宝箱双页**：banner-tab 切换、主视觉整张换、概率常驻可复看（含荣耀箱）、最近获得跨页留存。
5. **背包页**：四 tab + 空槽 + 来源跳转 + 换算；顶栏红点在素材入账后点亮。
6. 门槛全绿 + 22 条清单通过 + 四页改前/改后对照截图。回归断言复跑 `u2-troop.mjs`/`u2-team.mjs`/`u4-chests-materials.mjs`/`u4-gold10-verify.mjs`。
