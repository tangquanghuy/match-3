# SillyTavern 三消战斗推进计划

建立日期：2026-10-20。更新日期：2026-10-24。状态：执行中；P0 已落地，组装编译、宿主存档和再现战斗基础已实现，完整验收与最新证据见 STATUS.md。

产品依据：[产品任务书](../../docs/sillytavern-battle-product-plan.md)；需求追溯：[用户原话](../../docs/sillytavern-original-requirements.md)；执行进度：[STATUS.md](STATUS.md)。本文件负责执行顺序、交付物和验收，具体产品规则以产品任务书及用户后续澄清为准。

## 1. 本轮目标与范围

**交付人工测试的前提：发布后的三消网页经过真实 SillyTavern／酒馆助手／MVU 联调，支持助手嵌入与全屏，完成真实聊天变量与存档绑定验证。本地示例宿主可试玩仅作开发切片证据。**

交付同仓库内可在酒馆使用的三消附加模块：真实立绘与敌人组装 → 剧情战斗 → 结算和酒馆同步 → 图鉴、魂片与往昔再现 → 武器淬炼与本地存档管理。

P1 交付可操作且各稀有度适用敌人可组装覆盖率分别至少达到 90% 的敌人组装器；P2 交付真实酒馆中的战斗闭环试玩；P3 交付含养成的首个完整版本。武器萃取与重绑、多波次、首领阶段、重复刷材料模式、云同步和新资源制作保留在后续范围。

以下规则已经确定，执行时直接落实：

- 一个槽位绑定一个酒馆聊天，总量最多三档；第四个聊天由玩家手动删除旧档后创建，复制聊天产生新 ID 时创建独立新档。
- 图鉴与再现仅由剧情三消实际胜利解锁；记录敌方击败、我方倒下及复活、初末生命百分比和净变化。
- 再现保留原场完整敌方配置；我方使用当前队伍和装备的独立满血快照，不修改酒馆 HP 与剧情。
- 魂片可以先收藏，当前没有同伴或装配对象也照常学习；同一能力从任一来源学会，本档相同能力来源全部视为已学会。
- 以 20 / 14 / 10 / 7 / 5 次有效胜利作为五档测试基线，剧情首次胜利计入；每场每个有效击败且未学会的独立来源 +1，同源多只仅计一次。
- 再现只给未学会能力的魂片；整场全部能力学会后关闭挑战，保留图鉴与观看重放。重复刷材料玩法暂缓。
- 同伴颜色写入酒馆侧角色变量并持久化；无武器主角沿用 Common 的骑士之剑 `gw_KnightsSword`。
- 所有实际发奖都在本场结算页显示真实名称和实际数量，账本、实际入账、结算卡及报告一致。
- 敌人覆盖按各原始稀有度逐档验收，并附通用五档汇总，各档至少 90%；晋升度、淘宝模式、魔头专用技能依赖单列排除依据，普通首领与普通复杂机制保持在适配范围。

## 3. 里程碑与执行顺序

| 阶段 | 玩家或验收者得到什么 | 执行任务 | 阶段完成条件 |
| --- | --- | --- | --- |
| P0：设计与数据准备 | 具体页面行为清单、可用立绘入口、全量敌人与能力分类 | ST-01、ST-02、ST-03 | 页面状态有明确处理；四维资源可预览；逐档分母、特殊机制排除项与机制适配清单可查验 |
| P1：敌人组装器 | 能组装并预览覆盖各稀有度的真实敌方配置 | ST-04 | 各原始稀有度及通用五档分别至少 90% 适用敌人通过完整组装验收；配置可保存并保持一致 |
| P2：战斗闭环试玩 | 从酒馆开战，打完后看结算并继续剧情，可中断恢复 | ST-05、ST-06、ST-07 | 在真实酒馆完成胜败、中止、恢复和同步；旧结果重试保持账实一致 |
| P3：完整首版 | 图鉴、魂片收藏、再现、装配、淬炼、逐档备份 | ST-08、ST-09、ST-10 | 完成剧情首胜到能力学会及关闭再现的流程，养成与存档通过验收 |

推荐执行顺序：ST-01 → ST-03 全量清点 → ST-02 预览 → ST-04 逐档适配达标 → ST-05 → ST-06 → ST-07 → ST-08 → ST-09 → ST-10。先清点覆盖分母与机制缺口，再按覆盖需要安排适配工作。

ST-05 的宿主验证只依赖 ST-01，可以在能力整理期间提前验证，以尽早确认真实环境中的变量读取、存储和消息注入方式。未通过该项时继续推进预览与配方工作，P2 的真实接入完成标记留待验证。

按验收结果逐批推进；首轮没有运行数据前暂不承诺日历工期。每批结束更新状态、证据与下一项，新增需求先判断归属阶段。

## 4. 具体执行任务

### ST-01：把页面行为与数值标定项目落成验收清单（P0）

依赖：当前产品任务书。

交付物：新增 `docs/sillytavern-product-acceptance.md`，覆盖首次建档、满档管理、遭遇卡、战前准备、战斗、结算、队伍、武器、能力/图鉴、战报与存档的页面行为；每项写明玩家可见信息、操作条件、成功结果和异常后的去向。

同时登记待标定项目：职责的核心效果、各稀有度的能力复杂度与预算、法力成本、同色装配判定、等级/面板转换、淬炼成本与上限。数值字段采用有版本的测试基线，实际标定结果在 ST-04 与 ST-10 回填。

通过条件：每个入口都有前后去向；无同伴可收藏、无武器有默认、满三档手动删除、待同步结果可恢复等已定规则都有明确验收场景。现有规则足以确定的实现细节直接补齐。

### ST-02：接入四维立绘预览（P0）

依赖：ST-01；复用 `scripts/portrait-forms.mjs`、`data/portrait-forms.json` 及现有图片。

交付物：可操作的预览入口；颜色、稀有度、五形态、既有九职责联动筛选；真实卡片与候选数量；无候选时展示有图的修改选项；图片选择及内部绑定可保存。

通过条件：开放组合显示真实图片；完整颜色集合精确匹配；同条件重复打开保持绑定；换图保留设计条件；无候选清楚说明原因。当前已完成的标注与哈希检查沿用。

### ST-03：建立全量敌人与能力索引及逐档覆盖基线（P0）

依赖：ST-01。

交付物：全量敌人条目到主动及战斗被动/特质的映射、按实际配方和依赖去重的能力索引及统计；区分直接可用、需上下文绑定、需专门适配、现阶段不可用和范围外特殊机制；记录来源、目标、效果、缩放、法力成本、颜色读写、族群/召唤依赖、版本和中立描述。

按原始各稀有度统计总数、特殊机制排除数、适用数、当前通过数、缺口和达到 90% 所需通过数，再附通用五档汇总。晋升度、淘宝模式、魔头专用技能依赖建立逐条排除清单；普通复杂机制保留在适用分母。按所需机制家族和对逐档覆盖的影响安排适配批次，骑士之剑默认能力同时纳入验证。

通过条件：全量条目有明确分类与依据，原始稀有度与通用五档统计可重新生成；排除项逐条关联实际特殊机制依赖，优先按技能/特质排除，敌人其余独立的普通能力继续适配，整条敌人排除须符合主任务书第 4.5 节；机制家族任务能追溯到尚未覆盖的敌人。相同能力的去重规则可验证，敌人数与唯一配方数分别统计。适用分母为零的档位展示依据。

### ST-04：完成敌人组装器与完整阵容预览（P1）

依赖：ST-02、ST-03。

交付物：共享设计词表、约束编译、职责签名、单体及编队预算、持久蓝图；按 ST-03 清单适配达到各稀有度至少 90% 所需的机制，将能力与真实立绘组合成可在现有引擎执行的敌人；支持普通遭遇、精锐、单首领与最多四人阵容预览。

补齐与可用能力相对应的提示词说明及校验反馈，运行时 AI 使用语义设计，内部选图和配方标识由程序管理。达到逐档覆盖门槛所需的族群绑定、棋盘机制、召唤、变形和复杂条件在本任务完成；达标后剩余普通缺口列入后续扩展。

通过条件：运行时 AI 仅提交语义设计，由程序按主动／特质家族和组合约束装配；完整原子技能及固定联动组优先复用，底层战斗执行器保持现有实现。按伤害／状态／辅助／棋盘／资源／派生／条件分支等机制家族、目标时序及特质触发建立共享规则验证；补齐关键交互和 1～4 人端到端用例。

各原始稀有度及通用五档分别达到至少 90% 的适用敌人覆盖，每档通过数向上取整。通过数由全目录自动检查与已验证规则映射计算；不要求逐敌人手写测试或独立签收。同一规则未通过时，所有依赖条目自动成为缺口。自动检查包括立绘、完整主动／普通特质、目标、成本、颜色、缩放、依赖、说明、编译及派生预检；代表案例验证规则实际执行与组合效果。单纯打标、可编译或字段相等不替代行为证据。

当前已实现完整主动／独立有序特质的模块契约、语义分类装配与组合约束，以及规则驱动的全目录结构报告。新报告结构覆盖 1800／1821，各原始稀有度及五档均超过 90%；行为验收单列，不把可编译等同于全部规则已验证。关键组合独立复核和正式战场试玩入口已交付，可本地人工测试；最终整合 15 文件 409 项单测全通过，构建、定向 lint 和正式产物宿主 smoke 通过。五档预算与武器关系标定、各家族行为证据仍需继续补齐。既有来源测试只作回归样本，不继续按新增来源数量排任务。

### ST-05：验证真实酒馆桥接与宿主存档（P2 前置）

依赖：ST-01，可提前执行。

交付物：实际可用的桥接脚本或扩展路径、变量映射、消息入口、存储实现及启动自检；确认宿主 origin、稳定聊天标识、角色引用、装备实例、同伴颜色变量、HP/临时 HP 与两种数值模式的读取方式。

实现一聊天一档、总量三档，以及新聊天创建、切回旧档、满额手动删除、聊天切换时保留未完成数据。宿主拥有长期数据，战斗页使用本场快照。

通过条件：在真实酒馆读写变量、保存存档、发送请求及插入报告；重开恢复绑定；复制聊天新建独立档；第四档显示明确操作。记录使用的酒馆/桥接环境与手工验证步骤。测试宿主结果单独记录。

### ST-06：打通一场剧情三消与战果报告（P2）

依赖：ST-04、ST-05。

交付物：遭遇卡 → 准备页 → 战斗 → 本场结算 → 返回酒馆；接入最多四人的固定同行队伍、默认武器、装备首次稳定绑定、酒馆颜色变量、双方冻结配置及基础面板转换。

报告保存敌方逐对象击败与复活、我方曾倒下与复活、初末 HP/上限/百分比及净变化；累计伤害和治疗单列。临时 HP 独立吸收与回写，永久死亡及叙事后果交酒馆处理。

通过条件：同一场只由所选战斗方式扣血；满血与残血入场保持比例；三消终态正确回写；AI 能读取胜负和机械战果；默认武器可正常充能施法；未出场成员保持原状态。P2 起保存原场配置与战果，供后续养成读取。

### ST-07：补齐持久化、恢复和结算一致性（P2）

依赖：ST-06；逐行动保存接口在 ST-06 接入会话时一并预留。

交付物：确认行动后的宿主持久化、刷新恢复、放弃/中止、结果先保存、待同步队列、冲突处理、重复提交去重和旧消息重渲染处理。

把剧情三消的实际奖励明细、背包变更、结算卡与报告连接到同一结算结果，遵守 [发奖规范](../../docs/battle-settlement-rewards.md)。新增奖励类型同步补展示和对应回归。

通过条件：恢复后的棋盘与配置可复现；刷新、断连、关闭和重试保留已确认行动；重复结果只入账一次；失败与中止按实际结果发奖；切换聊天后旧结果只回到原档；ST 字段冲突时保留结果供处理。真实酒馆完成一次正常战斗、一次中断恢复和一次同步重试后，P2 才标记完成。

### ST-08：接入魂片收藏、图鉴与整场往昔再现（P3）

依赖：ST-07；复用 P2 保存的原场配置与战果。

交付物：胜利后图鉴、各来源进度、按配方共享的已学能力、同色技能装配、整场再现及观看重放。魂片收集始终独立于当前有无兼容同伴。

通过条件：

- 剧情首胜解锁并 +1；二十场档显示还需十九场，五场档显示还需四场。败北、撤退及 AIRP 胜利保持未解锁。
- 再现敌方保持原完整配置，我方使用当前队伍的独立满血快照；退出后酒馆 HP、临时 HP 与剧情保持原状态。
- 混编战逐来源推进；同源多只仅 +1；只有实际有效击败来源获得进度；失败与重复提交保持奖励正确。
- 相同能力任一来源学会后，本档已有及未来来源统一已学会；同场解锁只显示一次；有剩余未学能力时继续整场挑战，全部学会后关闭挑战。
- 再现只发本次实际魂片，结算显示名称、数量和进度；观看重放读取旧记录；单人收藏与同伴离队均保留进度。

### ST-09：完成武器淬炼、养成页面和逐档备份（P3）

依赖：ST-07；与 ST-08 共用同一份存档及结算接口。

交付物：队伍/武器/能力/战报与存档四类入口，剧情胜利材料、按能力代码共享的淬炼、加成上限及准确说明；逐档导入导出与绑定校验。

通过条件：剧情胜利材料在本场结算真实展示；淬炼成本和效果一致；原生酒馆装备面板保持其原规则；同代码共享进度；无武器使用固定默认配置；导入恢复对应聊天并遵守三档限制；新聊天保持独立。萃取、重绑与刷材料模式继续排在后续。

### ST-10：完成首版体验标定与交付验收（P3）

依赖：ST-08、ST-09。

交付物：真实试玩记录、数值版本、验收结果、已知限制和安装/恢复说明。试玩覆盖普通遭遇、混编队伍、单首领，1～4 人及不同技能组合；覆盖等级 1/10/20/49/50/95、经典/新版面板、残血、临时 HP 与不同武器档。

记录单场时长、行动数、施法频率、关键技能使用、胜败与倒下情况，以及学会能力的累计场次和耗时。优先验证首场有可见进度、前 1～2 场可首次淬炼、基础与收藏能力均有用途、控制/额外回合和恢复组合有合理边界。

通过条件：ST-01 验收项有实际证据；玩家走通“建档 → 剧情胜利 → 再现补齐 → 学会 → 装配 → 全学会关闭挑战 → 备份恢复”；原生模式的相关回归通过。20 / 14 / 10 / 7 / 5 和淬炼面板 20% 等目标的调整必须记录原因和体验证据。
